# ADR 0025：允许简单边界协议选择 Java record

## 状态

Accepted

## 背景

ADR 0005 和原基础开发规范曾全面禁止生产、测试、Command、DTO、View、Snapshot
和辅助类型使用 Java `record`。该规则保证了类型形态统一，但把领域对象需要受控
构造的要求扩大到了没有生命周期和领域行为的简单边界协议，增加了构造器、访问
方法和值相等实现的样板代码。

项目仍需要保证 Domain 不变量、JOOQ Entry 继承、框架代理和序列化绑定不被类型
选择破坏，同时允许简单不可变协议使用 Java 语言原生的值载体。

## 方案

### 方案一：继续全面禁止 record

所有项目自有类型继续使用 `class`。规则简单，但简单协议仍需维护样板代码。

### 方案二：按职责选择 class 或 record

Domain、持久化映射、复杂构造和需要框架代理的类型使用 `class`；简单不可变边界
协议可以选择 `record`，并通过测试验证框架和序列化兼容性。

### 方案三：全面允许 record

由每个开发者自由选择。这会使领域对象可能通过公开主构造器绕过 `create(...)`、
`rehydrate(...)` 和聚合行为，不满足当前领域建模要求。

## 决策

采用方案二：

- 聚合根、实体、值对象及其他拥有领域身份、生命周期、状态迁移或复杂不变量的
  Domain 类型必须使用 `class`。
- JOOQ Entry、数据库映射和需要继承生成父类的类型必须使用 `class`。
- 需要框架子类代理、受控构造、延迟初始化或复杂绑定的类型必须使用 `class`。
- 简单 Command、查询条件、边界请求/响应、不可变内部传输信封和测试参数可以在
  满足职责及框架约束时选择 `record`。
- `record` 中的集合、Map、数组和其他可变组件仍必须进行防御性复制。
- 现有 `final class` 不需要仅因本决策改写为 `record`。
- 代码审查按职责和不变量判断类型选择，不再仅因出现 `record` 判定违规。

详细选择规则由
[`development.md`](../standards/development.md) 维护。

## 理由

- 保留 Domain 受控构造和持久化边界，不降低领域建模约束。
- 允许简单协议直接表达不可变值语义，减少无业务价值的样板代码。
- 类型选择依据职责和框架能力，而不是使用单一语法禁令代替设计判断。
- 不强制迁移现有类型，避免产生无功能价值的大范围改动。

## 后果

- 原有扫描全部源码并禁止 `record` 的架构测试必须收敛为只检查禁止区域。
- Command 和边界协议可以逐步使用 `record`，但每次迁移必须验证序列化、反射、
  Micronaut 绑定和调用兼容性。
- ADR 0005 中“全面禁止 Java record”的条款被本 ADR 取代；其领域模型统一和
  String 技术 ID 决策继续有效。
