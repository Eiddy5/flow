# ADR 0128：存储查询直接使用生成表和字段

## 状态

Accepted（2026-10-16）。用户确认全部 jOOQ 存储使用 gen 生成的表名、字段，
不增加兼容代码。本决策细化 [ADR 0127](0127-use-generated-database-objects.md)。

## 背景

仅借用生成对象的名称，再复制表字段或创建无类型字段，会丢失生成的枚举、时间、
JSONB 和二进制类型，也使数据库结构变化无法在编译期暴露。

## 备选方案

1. 复制生成表元数据并维持旧字段辅助方法：不采用。
2. 仅将字符串替换成生成字段的 `getName()`：不采用。
3. Repository、状态存储、队列和 Java 数据迁移直接使用生成实例：采用。

## 决策

- 物理表使用 `Tables.X`；具体仓储通过具名配置取得对应的生成表类型，所有读写和
  条件优先使用该实例的字段。移除 `ConfiguredTable`、静态无类型字段、按名称重建
  字段及未知表的 `DSL.table` 兜底。
- 自定义物理表名使用生成表的 `rename(Name)`，查询别名使用 `as(...)`。
  在内部生成器的正式扩展点生成根据限定名称解析 schema 的 `getSchema()`，
  默认表仍不固定 schema，别名不附带 schema。不得手改生成文件或另写 Table 包装。
- 通用查询过滤器将 API 字段映射到当前生成表中已有的 Field；不存在的字段明确
  拒绝。排序白名单来自生成表字段并应用现有禁止排序集合，不再查询系统目录、接受
  生成模型之外的任意列。
- 保留原生 JSONB 载荷和可写字段集合。枚举直接使用生成枚举；领域枚举、Instant、
  队列 Long 游标等仅在值边界转换。物理 GENERATED ALWAYS 字段仍由数据库计算。
- 时间条件保留 PostgreSQL 原有跨时间类型比较，不为了适配 Java 类型转换物理列。
  聚合、窗口、全文函数、JSON 路径和 UTC 表达式可使用 SQL 模板，但实际物理字段
  必须作为生成 QueryPart 传入。CTE 和派生列由其所属查询解析。
- Flow 最新版本以窗口查询选出版本键，再关联真实生成表；草稿排除发生在计算最新
  版本前。外层筛选、全文检索、排序统一使用该生成表，避免丢失字段限定信息。
- 迁移历史的 JDBC 引导 DDL、锁和迁移顺序保持不变。Java 数据迁移只查询所需的
  生成 key/value，避免中间迁移阶段读取尚未创建的列。

## 理由

生成代码同时提供表、字段和数据库类型。直接消费它们才能让类型约束在编译期发挥
作用，并使配置后的表名、schema、别名和查询条件保持一致。

## 后果与验证

新增表需先维护迁移并重新生成，不能只配置陌生表名绕过模型。普通编译仍无需数据库。
验证覆盖生成类型、schema/别名、过滤与排序、真实 PostgreSQL 仓储、队列及根引擎。
执行证据及既有失败边界记录在 [生成指南](../harness/jooq-generation.md)。

Java 21 全模块编译及测试源码编译通过，gen 60 项、根引擎 16 项、PostgreSQL
984 项全部通过。全模块回归汇总 5,274 项（5,244 通过、26 跳过、4 项既有失败），
较首次 gen 接入归档无新增失败；运行隔离与来源校验通过。详见生成指南的日期记录。
