# ADR 0136 核心数据库保留触发器

## 状态

Accepted。扩展 ADR 0118 的退役范围，保留原生 Scheduler 和触发器。数据库规模与升级条款
已由 [ADR 0137](0137-provision-postgres-schema-explicitly.md) 修订。

## 背景

Flow 由 CSES 等 Java 宿主直接使用，主要负责流程定义、触发、执行和回查。指标历史、执行统计、SLA、跨流程拓扑索引、通用 KV、命名空间文件和并发准入各自引入了专用持久化和后台处理。旧有状态触发器复用了通用 KV 保存游标。

## 选项

1. 保持全部表与运行时能力，由宿主配置关闭可选功能。旧代码仍需要维护和验证。
2. 移除可选功能的专用表、服务和后台处理，将有状态触发器游标移到宿主提供的对象存储。采用。

## 决定

- 保留 `flows`、`executions`、`queues`、`triggers`、`multipleconditions`、`executordelayed`、`locks`、`logs`、`settings`、`service_instance`、`worker_job_running`、`task_outputs`、`execution_outputs`、`flow_migration_history`。
- Scheduler 继续使用 `triggers` 管理触发器状态，使用 `multipleconditions` 保存多条件触发窗口。普通 JDBC 投递、执行延迟、执行状态通知、任务图、文件输入和输出继续使用各自现有路径。
- 有状态触发器通过原有 `StatefulTriggerService` 接口读写宿主存储中的游标。读取使用当前租户和命名空间，按保存的过期时间及本次配置的条目 TTL 筛选。游标放在命名空间的 `_trigger_state` 私有目录，随同宿主存储持久化。
- 摘除指标历史和执行统计、SLA 监听、跨流程拓扑索引、通用 KV、命名空间文件以及流程、命名空间与租户级并发准入。运行期 Micrometer 指标继续由原有调用路径上报。已有执行状态枚举仍可反序列化历史记录。
- 新建基线跳过已退役功能的建表语句。旧库升级先复制当前有效的触发器游标，再删除当前 schema 中已退役的表，以及默认和当前配置前缀中的指标、统计和解除排队消息。旧数据库的记录 checksum 保持原值，迁移器只接受两组已知旧版本和当前基线之间的精确匹配。

## 理由

触发状态、多条件窗口和轮询游标与触发运行直接相关。让游标复用宿主存储可继续读取旧版本记录，也避免为可选业务保留整套通用 KV。常规任务与执行的文件通道也使用宿主存储。

## 后果与验证

- 升级前使用旧版本处理完 `QUEUED` 执行，再停止旧版运行角色。迁移发现仍有排队记录时会中止。存在有效游标的安装需要给迁移进程配置与旧版相同的宿主存储。
- 旧版通用 KV 和命名空间文件的底层对象继续留在宿主存储。删除表后，新的 Flow 运行时不再提供旧对象的索引和操作入口。
- 需要调整引用了退役插件及对应配置的流程和宿主调用。插件详情由当前全局目录生成。
- PostgreSQL 测试覆盖空库、两种旧 checksum、排队拦截、定向清理和游标在租户之间的隔离，验证入口见 [Java 接入指南](../harness/java-engine.md)。
