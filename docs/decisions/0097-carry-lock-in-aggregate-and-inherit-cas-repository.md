# ADR 0097：对象携带 lock 并继承 CAS 仓储

## 状态

Accepted（2026-09-10）。用户明确放宽“lock 不进入领域对象”的约束，要求按结构
直接调整，不保留兼容代码。本决策替代 ADR 0091 的元数据缓存与执行作用域，并修订
ADR 0071、0086 的技术版本归属；保留 ADR 0084、0087 的原子保存和无业务长事务边界。

## 背景与选项

隐藏版本需要额外保存对象身份、弱引用和生命周期。用户接受对象携带不参与业务规则的
技术字段后，继续维护该缓存已无必要。采用对象自带版本和实现层抽象仓储基类，不再
保留 CasSupport、FlowDatabase.execute、事务监听器或旧 rehydrate 重载。

## 决策

- Execution 直接携带 `Long lock`。新建为 null，首次 INSERT 后为 0；已保存版本
  非负。持久化恢复必须提供版本，copy 原样保留；replay 创建的新根保持 null。
- lock 是持久化元数据，不是业务版本，也不参与领域状态迁移、运行变量或 TaskRun
  规则。仅需 CAS 的根携带它，不给追加式 Flow 和聚合内 TaskRun 增加无用字段。
- 实现层 `CasRepository<T>` 统一公开 save、根 INSERT/CAS UPDATE、返回版本回填和
  冲突转换。具体仓储通过受保护方法提供对象版本读写及聚合保存 SQL，Entry 继续
  独占领域与数据库表示转换。基类没有请求状态和全局版本表。
- null 只尝试 INSERT，已有身份不能被覆盖；非空版本只 UPDATE，不存在也不能转为
  INSERT。条件完整包含租户、主键和查询时版本，成功更新递增 lock。保存前不能
  重新查询最新版本替换旧凭据。
- 根与 TaskRun 仍在单 SQL 中保存，退回的源根及派生根继续单 SQL 交接。SQL 失败
  不回填任何对象版本。冲突文案保持“数据已发生变化，请刷新后重试。”
- 普通 DSLContext 即可 find/save，不再需要会话。复制或跨操作传递的快照依靠自带
  版本竞争；不同副本互不推进版本，同一个可变对象不得被多个线程同时修改。
- 显式事务内成功 save 回填的是暂定版本；外层事务或 savepoint 回滚后，调用方必须
  丢弃已修改对象并重新加载，不复用它重试。没有自动回滚内存对象的兼容机制，也不
  增加跨 Worker 或多个 save 的业务长事务。

## 理由与后果

用一个技术字段替代隐式对象身份缓存，业务仍只调用 find/save。代价是对象公开结构
包含持久化版本，调用方必须保持版本与快照一起传递，不能自行修改版本或在回滚后
复用对象。数据库列已经是 lock，本轮不改变 Schema、生成代码或追加式 Flow 语义。

技术验证覆盖新建/恢复/copy/replay 的版本语义、跨仓储副本竞争、重复保存、陈旧或
已删除根拒绝、根子及双根原子性和事务回滚后重载。UC 预期不因技术结构调整而改变。
