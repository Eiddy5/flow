# ADR 0122：统一 Flow 包名、配置和运行标识

## 状态

Accepted（2026-10-14）。用户确认整个项目去除 Kestra 产品命名，Java 包统一为
`org.flow.*`，配置统一为 `flow.*`。修订 ADR 0115、0116、0121 中保留上游命名的条款。

## 背景

项目已经可以在同一应用中直接使用，但源码包、配置、插件清单和资源仍使用原产品
命名。只修改 Java import 会使反射、YAML 类型解析、插件生成和配置绑定失效。

## 备选方案

1. 仅修改公开入口，保留内部命名：需要长期维护两套命名，不采用。
2. 统一源码、资源、插件与配置，同时明确兼容边界：采用。
3. 改写来源清单、历史 SQL 和旧验收记录以消除所有文本：破坏来源与校验依据，不采用。

## 决策

- 所有自有 Java 源码和测试使用 `org.flow.*`，对应目录、SPI 文件名、反射字符串、
  YAML/JSON 任务类型、图标和 processor 生成资源同步修改。
- 两个原位于框架包下的本地覆盖类迁入 core 的 validations/retry。Micronaut 的
  SimpleRetry 为包内私有类型，按固定 4.10.28 源码带许可复制到本地 retry 包，
  保留算法和公开 RetryState 契约，避免继续在 `io.micronaut.*` 下放自有代码。
- 根与运行模块制品 group 为 `org.flow`，根依赖是 `org.flow:flow:2.0.5`；独立验证
  插件使用 `org.flow.fixture`。不保留旧包名适配壳，外部插件须重新编译。
- 应用配置和运行属性统一为 `flow.*`，环境变量统一为 `FLOW_*`；具名数据源仍为
  `datasources.flow`。当前配置示例和测试入口同步修改，不提供旧配置别名。
- 表达式已有 `flow.*` 用于流程身份，因此引擎环境和 URL 放在 `engine.environment`、
  `engine.url`，Worker 在本地重建 engine 配置，保留 wire 中的流程身份。
- 产品类名、日志、指标、插件清单 `X-Flow-*`、内部存储 URI `flow://`、脚本日志
  控制标记 `##flow:log:...##`、迁移历史表 `flow_migration_history` 使用 Flow 命名。
- 保持现有模块职责和执行能力。当前样例中指向原产品的数据及代码仓库地址改为
  明确的 `example.com` 占位值，运行前由调用者提供真实地址；二进制 HTTP 回归使用本地响应。
- 用户确认移除 `io.kestra:kotlp` 第三方二进制、对应选项与命令包装层。普通脚本执行、
  stdout/stderr、输出变量、文件和通用 OTLP 解析继续保留；不再自动采集 Kotlp 进程指标。
  根与 tooling 的运行依赖隔离检查拒绝重新引入该来源 group 的制品。
- 保留 LICENSE、UPSTREAM、不可变来源清单、原始构建快照、历史 ADR 与验收证据，
  历史 SQL 保持原文 checksum。当前变更通过逐文件迁移账本关联原路径和新路径。
- 两个预编译测试插件通过 `docs/harness/relocate-plugin-fixtures.py` 离线重定位，包含
  class 常量池、SPI、图标和 Manifest；许可证和 Maven 来源信息保持原样。
  脚本要求输入匹配固定来源哈希。这是测试资产迁移，不提供生产插件二进制兼容层。

## 理由

命名在源码、序列化、配置和插件发现之间形成完整约定，必须一起迁移。来源归属与
历史证据是事实记录，保留它们不意味着当前运行时继续依赖原产品命名。

## 后果与验证

这是开发阶段的不兼容命名切换。旧流程定义、插件 JAR、持久化类型和内部 URI 不自动
兼容；已有数据库和外部调用应用须另行迁移。本轮只在独立临时 PostgreSQL 和新 schema
中验证，不自动改动外部数据库。旧迁移历史表不能直接被当作当前历史表使用。

验证范围包括清理后全模块编译、插件和配置 Schema 导出、独立消费工程、真实
PostgreSQL 执行、插件加载、脚本、生命周期及完整回归。来源核对必须继续通过；
历史回归失败和本次新增失败分开记录，不以编译或专项成功替代完整回归结论。
本轮结果见 [Java 使用指南](../harness/java-engine.md#2026-10-14-命名迁移专项)。
