# UC 用户场景

## 文档定位

`docs/uc/` 保存基于已确认用户需求整理的真实用户场景。UC 描述谁在什么业务状态下
执行什么操作、能够观察到什么结果，以及如何结束本次场景。

UC 不描述代码如何实现，也不验证技术架构。技术架构、生产代码、测试代码、运行
结果和能力缺口都不能定义或改变 UC 预期；架构符合性由独立的架构规范和技术测试
验证。

## 权威规则

UC 的创建、更新、格式和校验规则只由
[`$generate-uc`](../../.codex/skills/generate-uc/SKILL.md) 定义。
UC Agent 负责确认用户需求、划分场景和管理目录，本 README 只说明目录定位和索引，
不复制另一套生成规则。

当前 UC 按主要验证对象分为流程编排、流程运行和任务类型。每个 UC 只有一个主要
类型；具体 Task 类型的 UC 使用标准验证流程形成完整用户闭环。

## 目录结构

UC 按业务领域归档：

```text
docs/uc/
  README.md
  flow/
    README.md
    UC-01 Flow 草稿生命周期与多租户管理.md
    UC-02 用户启动、查询与取消 Flow.md
    UC-04 用户恢复处于 Pause 的 Flow.md
    UC-05 用户处理包含并行 Pause 的 Flow.md
    UC-06 用户使用 Pause 结果选择 Flow 路径.md
    UC-07 用户处理包含多阶段 Pause 的 Flow.md
    UC-08 用户在流程中输出动态日志.md
    UC-09 用户定义并运行循环流程.md
```

新领域由 UC Agent 创建，同时建立领域 `README.md` 并维护领域边界、UC 清单、
依赖和推荐验证顺序。

`gaps/` 仅保留历史实现差距，不参与定义或修改 UC。

## 测试关系

```text
一个 UC Markdown
  -> 一个主测试类
  -> 场景 S*
  -> 场景中的预期结果与结束状态
  -> 测试断言和执行证据
  -> 场景结论
```

Test Agent 只验证用户可观察结果，不把 ADR、模块边界、持久化方式或其他技术架构
约束追加为 UC 断言，也不得为了让当前实现通过而放宽用户场景。
