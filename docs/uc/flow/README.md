# Flow UC 领域

## 领域边界

本目录保存用户管理 Flow 草稿与定义删除、启动和取消 Flow、按定义推进流程、恢复
Pause、处理并行 Pause、使用 Pause 结果选择条件路径、完成多阶段 Flow、输出动态
日志以及运行循环 Flow 的用户场景。

所有 UC 的用户操作对象都是 Flow 及其运行实例。Pause 是 Flow 中受验证的 Task
类型，不定义独立的外派任务、待办或受理业务对象。

## UC 格式

所有 UC 已迁移到 `$generate-uc` 四章节格式，只描述真实用户场景：

- 每个 UC 明确标识为流程编排、流程运行或任务类型。
- 用户从可见的 Flow 业务状态开始。
- 用户通过 Flow 查询识别草稿、正式定义、运行实例或当前 Pause 步骤。
- 用户执行真实操作并重新查询 Flow 结果。
- 每个场景独立完成、取消、失败、明确未创建或完成资源清理。

任务类型 UC 必须在每个场景定义并发布标准验证 Flow，启动独立运行实例，观察目标
Task 结果并证明结果被后续步骤消费。Flow 运行到 Pause 时，用户通过 Flow 的运行
信息查询并识别具体 Pause，向查询所得 Pause 提交结果，再查询后续 Pause 和 Flow
终态。不能脱离 Flow 直接验证 Pause，也不能把 Pause 描述成独立外派任务。

## 推荐验证顺序

```text
UC-01 -> UC-02 -> UC-04 -> UC-06 -> UC-09 -> UC-05 -> UC-07 -> UC-08
```

UC-01 建立 Flow 定义基础；UC-02 验证启动、查询和推进；UC-04 验证 Pause；
UC-06、UC-05 分别验证 Pause 结果条件路径和显式并行；
UC-07 综合验证多阶段 Pause 编排。UC-08 验证日志步骤从运行结果提取消息、输出
日志并继续 Flow。UC-09 在结果条件基础上验证固定次数与条件循环。
