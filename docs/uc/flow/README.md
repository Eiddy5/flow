# Flow UC 领域

## 领域边界

本目录保存用户管理 Flow 草稿与定义删除、启动和取消流程、运行自动流程、处理
外派任务、处理并行任务、选择条件路径、完成多阶段长流程以及输出动态日志的 UC。
本目录同时覆盖用户按固定次数或本轮结果编排和运行循环流程的用户闭环。

## UC 格式

所有 UC 已迁移到 `$generate-uc` 四章节格式，只描述真实用户场景：

- 每个 UC 明确标识为流程编排、流程运行或任务类型。
- 用户从可见业务状态开始。
- 用户通过查询识别要操作的草稿、流程或任务。
- 用户执行真实操作并重新查询结果。
- 每个场景独立完成、取消、失败、明确未创建或完成资源清理。

任务类型 UC 必须在每个场景定义并发布标准验证流程，启动独立流程实例，观察目标
任务结果并证明结果被后续步骤消费。流程等待外派处理时，被外派用户必须从自己的
待办中查询具体任务，完成查询所得任务，再查询后续待办和流程结果。不能把等待
状态作为正常场景的结束。

## 推荐验证顺序

```text
UC-01 -> UC-02 -> UC-03 -> UC-04 -> UC-06 -> UC-09 -> UC-05 -> UC-07 -> UC-08
```

UC-01 建立流程定义基础；UC-02 验证启动和推进；UC-03、UC-04 分别验证自动执行任务和
外派等待任务；UC-06、UC-05 分别验证条件和并行编排；UC-07 综合验证多阶段编排。
UC-08 验证日志步骤从运行结果提取消息、输出日志并继续流程。
UC-09 在自动步骤和结果条件基础上验证固定次数与条件循环的逐轮编排。
