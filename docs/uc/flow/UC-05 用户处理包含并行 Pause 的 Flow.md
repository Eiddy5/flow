# UC-05 用户处理包含并行 Pause 的 Flow

## 验证标识

- UC：`UC-05`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`流程编排`
- 需求基线：`用户确认的 Flow Pause 与显式并行规则@2026-08-27`
- 依赖：`UC-03`、`UC-04`

## 验证目标

验证用户只有在 Flow 中显式添加并行节点时，节点下的两个 Pause 分支才会同时进入
等待并可分别恢复；只有两个分支都恢复完成后才执行一次汇总和结束步骤。普通同级
步骤不被隐式解释为并行，恢复顺序、重复提交和中途取消不会造成提前或重复汇总。

## 验证场景

### S1 用户恢复 Flow 中的两个并行 Pause

- 参与用户：Flow 编辑用户、Flow 发起用户和 Flow 处理用户
- 开始状态：用户可以定义显式并行节点，节点下包含后端检查和前端检查两个 Pause 分支，之后是汇总步骤
- 用户操作：用户编辑并发布 Flow、启动运行实例，查询到两个并行 Pause；逐个提交结果并在每次提交后重新查询 Flow，最后查询汇总和最终结果
- 预期结果：两个 Pause 分支相互独立，全部恢复完成后只执行一次汇总和一次结束步骤
- 场景结束：Flow 已完成，没有等待恢复的 Pause

### S2 最后一个 Pause 恢复后才汇总

- 参与用户：Flow 编辑用户、Flow 处理用户和 Flow 发起用户
- 开始状态：用户可以定义两个检查 Pause 位于同一显式并行节点下，并在节点之后设置汇总
- 用户操作：用户编辑并发布 Flow、启动运行实例；恢复第一个 Pause 后查询中间结果，再查询并恢复第二个 Pause
- 预期结果：第一个 Pause 恢复时不执行汇总，第二个 Pause 恢复后只执行一次汇总
- 场景结束：Flow 已完成，没有等待恢复的 Pause

### S3 只恢复一个 Pause 时禁止提前汇总

- 参与用户：Flow 编辑用户、Flow 发起用户和 Flow 处理用户
- 开始状态：用户可以定义后端检查和前端检查两个 Pause 位于同一显式并行节点下，节点之后执行汇总
- 用户操作：用户编辑并发布 Flow、启动运行实例；只恢复后端检查 Pause 并查询中间结果，随后重新查询并恢复前端检查 Pause
- 预期结果：前端检查 Pause 未恢复时不会出现汇总或结束结果，恢复剩余 Pause 后 Flow 才继续
- 场景结束：Flow 已完成，没有遗留等待恢复的 Pause

### S4 用户重复恢复同一个并行 Pause

- 参与用户：Flow 编辑用户、Flow 发起用户和 Flow 处理用户
- 开始状态：用户可以定义后端检查和前端检查两个 Pause 位于同一显式并行节点下，节点之后执行汇总
- 用户操作：用户编辑并发布 Flow、启动运行实例；恢复后端检查 Pause 后再次向同一 Pause 提交结果，重新查询后恢复前端检查 Pause 并查询最终结果
- 预期结果：重复提交被明确拒绝，不会重复记录后端结果或提前执行汇总
- 场景结束：合法恢复前端检查 Pause 后 Flow 已完成

### S5 用户反转两个并行 Pause 的恢复顺序

- 参与用户：Flow 编辑用户、Flow 发起用户和 Flow 处理用户
- 开始状态：用户可以定义后端检查和前端检查两个 Pause 位于同一显式并行节点下，节点之后执行汇总
- 用户操作：用户编辑并发布 Flow，启动两个运行实例；一个实例按后端到前端恢复，另一个按前端到后端恢复，每次提交后都重新查询
- 预期结果：两种顺序的最终业务结果、Pause 归属和汇总次数一致
- 场景结束：两个 Flow 运行实例都已完成且各自只汇总一次

### S6 用户恢复一个并行 Pause 后取消 Flow

- 参与用户：Flow 编辑用户、Flow 发起用户和 Flow 处理用户
- 开始状态：用户可以定义后端检查和前端检查两个 Pause 位于同一显式并行节点下，节点之后执行汇总
- 用户操作：用户编辑并发布 Flow、启动运行实例；恢复一个 Pause 后取消 Flow，再尝试恢复剩余 Pause，并重新查询 Flow 和步骤历史
- 预期结果：取消后剩余恢复请求被拒绝，不会执行汇总或结束步骤
- 场景结束：Flow 已取消，没有等待恢复的 Pause

## 验证方式

### S1

1. 用户编辑并发布包含显式并行节点、两个 Pause 分支和后续汇总的 Flow，再启动运行实例。
2. 用户查询到后端检查和前端检查两个 Pause，恢复第一个后重新查询剩余 Pause。
3. 用户恢复第二个 Pause，再查询汇总、结束结果和完整历史。
4. 用户确认 Flow 已完成、只汇总一次且没有等待恢复的 Pause。

### S2

1. 用户编辑并发布两个 Pause 分支全部恢复后才汇总的 Flow，再启动运行实例。
2. 用户查询两个并行 Pause，恢复第一个并确认另一个仍在等待且没有汇总结果。
3. 用户重新查询并恢复第二个 Pause。
4. 用户确认汇总只执行一次且 Flow 已完成。

### S3

1. 用户编辑并发布包含两个并行 Pause 的 Flow，再启动运行实例。
2. 用户恢复后端检查 Pause 并查询 Flow 中间结果。
3. 用户确认汇总和结束结果尚未出现，再重新查询并恢复前端检查 Pause。
4. 用户确认 Flow 已完成且没有等待恢复的 Pause。

### S4

1. 用户编辑并发布包含两个并行 Pause 的 Flow，再启动并查询两个 Pause。
2. 用户恢复后端检查 Pause，然后再次向同一 Pause 提交结果并观察明确拒绝。
3. 用户重新查询，确认前端检查仍是唯一等待恢复的 Pause 且没有汇总，再恢复前端检查。
4. 用户确认 Flow 已完成且只汇总一次。

### S5

1. 用户编辑并发布包含两个并行 Pause 的 Flow，启动两个独立运行实例并分别查询两个 Pause。
2. 用户按相反顺序恢复两组 Pause，每次提交后都重新查询剩余 Pause。
3. 用户查询两个实例的最终业务结果、Pause 归属和汇总次数。
4. 用户确认两个 Flow 运行实例都已完成且结果等价。

### S6

1. 用户编辑并发布包含两个并行 Pause 的 Flow，再启动并查询两个 Pause。
2. 用户恢复其中一个 Pause 后取消 Flow，再尝试恢复另一个 Pause。
3. 用户查询 Flow 状态、汇总结果和步骤历史。
4. 用户确认 Flow 已取消、恢复请求被拒绝且没有等待恢复的 Pause。
