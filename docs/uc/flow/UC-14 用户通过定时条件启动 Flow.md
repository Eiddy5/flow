# UC-14 用户通过定时条件启动 Flow

## 验证标识

- UC：`UC-14`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`流程运行`
- 需求基线：`用户确认的 Flow 内配置触发器、独立触发和第一阶段定时能力@2026-09-14`
- 依赖：`UC-01、UC-02`

## 验证目标

用户可以通过 Flow 自身配置的定时条件自动启动流程；每个触发器独立生效，一个条件
满足即可启动一次，两个触发器同时满足时分别启动，并能查询本次产生的所有运行实例直至完成。

## 验证场景

### S1 一个定时条件满足即可启动流程

- 参与用户：Flow 管理用户
- 开始状态：用户已有一个只有单一正式版本、能自动完成的简单 Flow；该 Flow 配置两个定时触发器，本次观察期间只有第一个触发器的计划时间到达；系统持续可用，没有其他启动操作
- 用户操作：用户查询 Flow 的定时配置和现有运行记录；在第一个计划时间到达前后重新查询运行记录，识别本次新产生的实例，并查询其最终结果
- 预期结果：计划时间到达前没有新增实例；第一个条件满足后只新增一个实例，不需要等待第二个条件满足，也不需要用户手动启动；该实例按所选 Flow 完整运行
- 场景结束：本次新增的运行实例已完成，没有活动步骤；观察结束早于后续计划时间

### S2 两个定时触发器同时满足分别启动流程

- 参与用户：Flow 管理用户
- 开始状态：用户已有一个只有单一正式版本、能自动完成的简单 Flow；该 Flow 配置两个独立定时触发器，二者在同一计划时间满足；系统持续可用，没有其他启动操作
- 用户操作：用户查询并确认两个定时配置，记录现有运行实例；计划时间到达后重新查询，识别本次新增的两个实例，分别查询完整运行结果
- 预期结果：本次新增两个编号不同的运行实例，两个触发器的命中不会合并为一次启动；两个实例都按所选 Flow 完整运行
- 场景结束：本次新增的两个运行实例均已完成，没有活动步骤；观察结束早于后续计划时间

## 验证方式

### S1

1. 用户通过 Flow 查询能力选择上述简单 Flow，确认 Flow 自身保存两个定时配置，记录当前运行实例。
2. 用户在第一个计划时间前查询，确认没有本次新增实例；计划时间到达后再次通过运行查询识别新增实例。
3. 用户在第二个条件尚未满足且没有手动启动的期间，确认只新增一个实例，并按其运行编号查询步骤历史和结果。
4. 用户在后续计划时间前确认本次实例已完成且没有活动步骤。

### S2

1. 用户通过 Flow 查询能力选择上述简单 Flow，确认其中两个独立定时配置在同一计划时间满足，并记录当前运行实例。
2. 用户在计划时间到达后通过运行查询识别新增实例，确认恰好新增两个且运行编号不同。
3. 用户分别按运行编号查询两个实例的步骤历史和结果，确认两次启动均完整执行。
4. 用户在后续计划时间前确认本次两个实例均已完成且没有活动步骤。
