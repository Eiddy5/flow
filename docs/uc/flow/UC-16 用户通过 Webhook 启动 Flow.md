# UC-16 用户通过 Webhook 启动 Flow

## 验证标识

- UC：`UC-16`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`流程运行`
- 需求基线：`用户确认的外部 HTTP 请求通过 Webhook 触发 Flow@2026-09-17`
- 依赖：`UC-01、UC-02`

## 验证目标

用户通过外部 HTTP 请求命中 Flow 自身配置的 Webhook，启动一次目标流程，并能查询
该次运行的完整结果。

## 验证场景

### S1 合法 Webhook 请求启动目标 Flow

- 参与用户：具有目标 Flow 访问及启动权限的同租户用户
- 开始状态：用户已有一个只有单一正式版本、配置一个 Webhook 触发器且能自动完成的简单 Flow；用户已具备有效访问身份和合法请求数据，本次未发送触发请求，系统持续可用且没有其他启动操作
- 用户操作：用户查询 Flow 的 Webhook 配置和已有运行记录，通过对应的公开 HTTP 触发入口发送一次合法请求；随后重新查询目标 Flow 的运行实例，识别本次新增实例并查询最终结果
- 预期结果：合法请求被受理，目标 Flow 只新增一个运行实例，用户无需再调用普通流程启动入口；新增实例按目标 Flow 定义完整执行
- 场景结束：本次新增运行实例已完成，没有活动步骤或等待处理的任务

## 验证方式

### S1

1. 用户通过公开 Flow 查询选择目标，确认其 Webhook 配置，准备合法身份及请求数据，并记录已有运行实例。
2. 用户通过该 Webhook 对应的公开 HTTP 入口发送一次合法请求，观察请求被受理。
3. 用户通过目标 Flow 的运行查询识别新增实例，确认只新增一个，并按运行编号查询步骤历史和结果。
4. 用户重新查询确认本次实例已完成，没有活动步骤或等待处理的任务。
