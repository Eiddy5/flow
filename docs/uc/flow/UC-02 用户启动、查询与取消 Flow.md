# UC-02 用户启动、查询与取消 Flow

## 验证标识

- UC：`UC-02`
- 状态：`ACCEPTED`
- 领域：`flow`
- 需求基线：`用户确认的 Flow 完整用户路径规则@2026-07-28`
- 依赖：`UC-01`

## 验证目标

验证用户只能启动当前可用的 Flow，运行中的流程始终使用启动时选定的正式版本，
并且用户能够查询和取消准确的目标；每条用户路径最终完成、取消、失败或明确未创建。

## 验证场景

### S1 用户启动并完成当前版本

- 参与用户：流程发起用户和被外派用户
- 开始状态：版本 1 是当前可用版本，流程中包含一个外派任务
- 用户操作：发起用户启动并查询流程，被外派用户查询和完成自己的任务，发起用户再查询最终结果
- 预期结果：只创建一个运行流程，该流程始终使用版本 1，外派任务完成后继续执行并最终完成
- 场景结束：流程已完成，没有遗留待处理外派任务

### S2 新版本发布前后的流程分别完整运行

- 参与用户：旧流程发起用户、新流程发起用户和各自的被外派用户
- 开始状态：旧流程使用版本 1 等待外派处理，随后版本 2 发布
- 用户操作：用户启动版本 2 对应的新流程，两组被外派用户分别查询并完成自己的任务，最后查询两个流程
- 预期结果：旧流程始终使用版本 1，新流程使用版本 2，两个流程的任务和运行历史互不混用
- 场景结束：两个流程都已完成且没有遗留待处理任务

### S3 用户取消准确的目标流程

- 参与用户：目标流程发起用户、对照流程发起用户和对照流程的被外派用户
- 开始状态：目标流程和对照流程都在等待外派处理
- 用户操作：用户查询并取消目标流程，再查询两个流程；对照流程的被外派用户查询并完成自己的任务
- 预期结果：只有目标流程被取消，对照流程不受影响并继续完成
- 场景结束：目标流程已取消，对照流程已完成

### S4 用户启动不可用或不可见的 Flow

- 参与用户：普通用户和另一租户的用户
- 开始状态：目标 Flow 分别处于未发布、已关闭、不存在或属于其他租户
- 用户操作：用户逐一请求启动，并在每次拒绝后查询自己的运行流程
- 预期结果：每次启动都被明确拒绝，不会错误启动其他版本或其他租户的 Flow
- 场景结束：没有创建任何运行流程或待办

### S5 用户取消不存在、越权或已经结束的流程

- 参与用户：普通用户、另一租户用户和合法对照流程的被外派用户
- 开始状态：目标分别不存在、属于其他租户、已经完成或已经取消
- 用户操作：用户逐一请求取消并重新查询；若存在合法对照流程，被外派用户查询并完成其任务
- 预期结果：所有错误取消都被明确拒绝，目标和对照流程的状态、历史及待办不发生越权变化
- 场景结束：原终态保持不变，合法对照流程已完成

### S6 流程等待期间发布新版本

- 参与用户：旧流程发起用户、新流程发起用户和被外派用户
- 开始状态：旧流程使用版本 1 等待外派处理
- 用户操作：用户发布版本 2，被外派用户查询并完成旧流程任务，随后用户启动并完成新流程，再查询两个结果
- 预期结果：旧流程不会切换到版本 2，新流程使用版本 2，两条运行路径均按各自版本执行
- 场景结束：新旧两个流程都已完成

### S7 完成外派任务与取消流程发生竞争

- 参与用户：流程发起用户和被外派用户
- 开始状态：流程正在等待一个已经被用户查询到的外派任务
- 用户操作：发起用户取消流程，同时被外派用户完成该任务，竞争结束后双方重新查询流程和待办
- 预期结果：完成和取消最多只有一个生效，最终结果只能是已完成或已取消，不能出现相互矛盾的历史
- 场景结束：流程已完成或已取消，没有遗留待处理任务

## 验证方式

### S1

1. 用户发布版本 1 并启动流程。
2. 发起用户查询运行状态，被外派用户从自己的待办中查询具体任务并完成。
3. 用户重新查询流程、步骤历史和待办，确认只运行一个流程且始终使用版本 1。
4. 用户确认流程已完成且待办查询为空。

### S2

1. 用户启动版本 1 流程并查询到外派等待状态。
2. 用户发布版本 2 并启动第二个流程。
3. 两组被外派用户分别查询和完成自己的任务，再查询两个流程的版本与历史。
4. 用户确认两个流程都已完成且相互隔离。

### S3

1. 用户启动目标流程和对照流程，并查询到两个独立待办。
2. 用户取消目标流程并重新查询目标状态。
3. 对照流程的被外派用户查询并完成自己的任务。
4. 用户查询并确认目标已取消、对照已完成。

### S4

1. 用户准备未发布、已关闭、不存在和其他租户的 Flow。
2. 用户分别请求启动这些 Flow。
3. 每次拒绝后，用户查询自己的运行流程和待办数量。
4. 用户确认没有创建任何运行流程或待办。

### S5

1. 用户准备不存在、越权、已完成和已取消的目标，并准备一个合法对照流程。
2. 用户分别发起取消请求并观察明确拒绝。
3. 用户重新查询所有目标，确认状态、历史和待办没有变化。
4. 被外派用户完成合法对照任务，用户查询并确认对照流程已完成。

### S6

1. 用户启动版本 1 流程并查询到外派任务。
2. 用户发布版本 2，被外派用户完成版本 1 流程的待办。
3. 用户启动版本 2 流程，被外派用户查询并完成其待办。
4. 用户查询并确认两个流程分别使用原版本且都已完成。

### S7

1. 用户启动流程，被外派用户查询并记录自己的待办。
2. 发起用户取消流程，同时被外派用户提交完成。
3. 双方重新查询流程状态、步骤历史和待办数量。
4. 用户确认只有一个结果生效，流程已完成或已取消且没有遗留待办。
