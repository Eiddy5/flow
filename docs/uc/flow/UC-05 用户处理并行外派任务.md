# UC-05 用户处理并行外派任务

## 验证标识

- UC：`UC-05`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`流程编排`
- 需求基线：`用户确认的默认串行与显式并行规则@2026-07-30`
- 依赖：`UC-03`、`UC-04`

## 验证目标

验证用户只有在流程中显式添加并行节点时，节点下的两个外派分支才会同时出现并可
分别完成；只有两个分支都完成后才执行一次汇总和结束步骤。普通同级任务不被隐式
解释为并行，完成顺序、重复提交和中途取消不会造成提前或重复汇总。

## 验证场景

### S1 用户查询并完成两个并行外派任务

- 参与用户：Flow 编辑用户、流程发起用户和被外派用户
- 开始状态：用户可以定义显式并行节点，节点下包含后端检查和前端检查两个分支，之后是汇总步骤
- 用户操作：编辑并发布包含显式并行节点的流程，发起用户启动；被外派用户查询两个任务，逐个完成并在每次完成后查询剩余任务，最后查询流程结果
- 预期结果：两个任务相互独立，全部完成后只执行一次汇总和一次结束步骤
- 场景结束：流程已完成，没有待处理外派任务

### S2 最后一个任务完成后才汇总

- 参与用户：Flow 编辑用户、被外派用户和流程发起用户
- 开始状态：用户可以定义两个检查位于同一显式并行节点下，并在节点之后设置汇总
- 用户操作：编辑并发布包含显式并行节点的流程，发起用户启动；被外派用户完成第一个任务后查询中间结果，再查询并完成第二个任务
- 预期结果：第一个任务完成时不执行汇总，第二个任务完成后只执行一次汇总
- 场景结束：流程已完成，没有待处理任务

### S3 只完成一个任务时禁止提前汇总

- 参与用户：Flow 编辑用户、流程发起用户和被外派用户
- 开始状态：用户可以定义后端检查和前端检查位于同一显式并行节点下，节点之后执行汇总
- 用户操作：编辑并发布包含显式并行节点的流程，发起用户启动；被外派用户只完成后端检查并查询中间结果，随后重新查询并完成前端检查
- 预期结果：前端检查未完成时不会出现汇总或结束结果，完成剩余任务后流程继续
- 场景结束：流程已完成，没有遗留外派任务

### S4 用户重复完成同一个并行任务

- 参与用户：Flow 编辑用户、流程发起用户和被外派用户
- 开始状态：用户可以定义后端检查和前端检查位于同一显式并行节点下，节点之后执行汇总
- 用户操作：编辑并发布包含显式并行节点的流程，发起用户启动；被外派用户完成后端检查后再次提交完成，重新查询后完成前端检查并查询最终结果
- 预期结果：重复完成被明确拒绝，不会重复记录后端结果或提前执行汇总
- 场景结束：合法完成前端检查后流程已完成

### S5 用户反转两个任务的完成顺序

- 参与用户：Flow 编辑用户、流程发起用户和被外派用户
- 开始状态：用户可以定义后端检查和前端检查位于同一显式并行节点下，节点之后执行汇总
- 用户操作：编辑并发布包含显式并行节点的流程，发起用户启动两个实例；一个流程按后端到前端完成，另一个按前端到后端完成，每次完成后都重新查询
- 预期结果：两种顺序的最终业务结果、任务归属和汇总次数一致
- 场景结束：两个流程都已完成且各自只汇总一次

### S6 用户完成一个并行任务后取消流程

- 参与用户：Flow 编辑用户、流程发起用户和被外派用户
- 开始状态：用户可以定义后端检查和前端检查位于同一显式并行节点下，节点之后执行汇总
- 用户操作：编辑并发布包含显式并行节点的流程，发起用户启动；被外派用户完成一个任务后，发起用户取消流程，被外派用户尝试完成剩余任务，双方再查询流程和待办
- 预期结果：取消后剩余完成请求被拒绝，不会执行汇总或结束步骤
- 场景结束：流程已取消，没有待处理外派任务

## 验证方式

### S1

1. 编辑并发布包含显式并行节点、两个检查分支和后续汇总的流程，发起用户启动，被外派用户查询到后端检查和前端检查。
2. 用户完成第一个任务并重新查询剩余待办。
3. 用户完成第二个任务，再查询汇总、结束结果和完整历史。
4. 用户确认流程已完成、只汇总一次且待办为空。

### S2

1. 编辑并发布包含显式并行节点且两个分支全部完成后才汇总的流程，发起用户启动，被外派用户查询两个并行任务并记录各自业务归属。
2. 用户完成第一个任务并查询，确认另一个仍待处理且没有汇总结果。
3. 用户重新查询并完成第二个任务。
4. 用户确认汇总只执行一次且流程已完成。

### S3

1. 编辑并发布包含显式并行节点、后端和前端两个分支的流程，发起用户启动，被外派用户查询两个待办。
2. 用户完成后端检查并查询流程中间结果。
3. 用户确认汇总和结束结果尚未出现，再重新查询并完成前端检查。
4. 用户查询并确认流程已完成且没有遗留待办。

### S4

1. 编辑并发布包含显式并行节点、后端和前端两个分支的流程，发起用户启动，被外派用户查询并完成后端检查。
2. 用户再次提交后端检查完成结果并观察明确拒绝。
3. 用户重新查询，确认前端检查仍是唯一待办且没有汇总，再完成前端检查。
4. 用户查询并确认流程已完成且只汇总一次。

### S5

1. 编辑并发布包含显式并行节点、后端和前端两个分支的流程，发起用户启动两个独立实例并分别查询两个并行任务。
2. 用户按相反顺序完成两组任务，每次完成后都重新查询剩余待办。
3. 用户查询两个流程的最终业务结果、任务归属和汇总次数。
4. 用户确认两个流程都已完成且结果等价。

### S6

1. 编辑并发布包含显式并行节点、后端和前端两个分支的流程，发起用户启动，被外派用户查询两个并行任务并完成其中一个。
2. 发起用户取消流程，被外派用户尝试完成另一个任务。
3. 双方查询流程状态、汇总结果和待办。
4. 用户确认流程已取消、完成请求被拒绝且待办为空。
