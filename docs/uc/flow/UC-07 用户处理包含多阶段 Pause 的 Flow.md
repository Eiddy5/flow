# UC-07 用户处理包含多阶段 Pause 的 Flow

## 验证标识

- UC：`UC-07`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`流程编排`
- 需求基线：`用户确认的 Flow Pause 多阶段编排@2026-08-27`
- 依赖：`UC-04`、`UC-05`、`UC-06`

## 验证目标

验证包含多层串行业务步骤、显式并行 Pause、汇总和后续安全批准 Pause 的长 Flow
能够形成完整用户旅程：普通同级步骤按声明顺序推进，只有用户添加的并行节点才会
同时进入多个 Pause；用户每次查询当前 Flow 并恢复当前 Pause，直至 Flow 结束。

## 验证场景

### S1 用户完成包含多阶段 Pause 的 Flow

- 参与用户：Flow 编辑用户、Flow 发起用户和各阶段 Flow 处理用户
- 开始状态：用户可以定义包含准备、显式并行复核 Pause、汇总、安全批准 Pause、发布和通知的多阶段 Flow
- 用户操作：编辑用户定义并发布多阶段 Flow，发起用户启动；处理用户查询当前实例，依次恢复并行节点下的两个复核 Pause 和之后出现的安全批准 Pause
- 预期结果：复核结果归属正确，只汇总一次，安全批准 Pause 只在复核汇总后出现，全部十二个业务步骤各执行一次
- 场景结束：Flow 已完成，没有等待恢复的 Pause

### S2 用户在每个 Pause 阶段重新查询 Flow

- 参与用户：Flow 编辑用户、Flow 处理用户和 Flow 发起用户
- 开始状态：用户可以定义显式并行复核 Pause，复核汇总完成后才进入安全批准 Pause
- 用户操作：编辑用户定义并发布多阶段 Flow，发起用户启动并只保留运行编号；处理用户查询两个复核 Pause，恢复一个后重新查询，恢复另一个后再查询新出现的安全批准 Pause 并提交结果
- 预期结果：每次查询只显示当前实例真实等待恢复的 Pause，未来阶段的 Pause 不会提前出现
- 场景结束：Flow 已完成，最后一次查询没有等待恢复的 Pause

### S3 用户发布包含跨层重复 Pause 标识的 Flow

- 参与用户：Flow 编辑用户
- 开始状态：不同层级的 Pause 步骤使用了重复的业务标识
- 用户操作：用户请求发布，收到拒绝后查询正式版本和运行实例
- 预期结果：发布因重复标识被明确拒绝，不产生正式版本或运行实例
- 场景结束：本场景没有创建任何运行资源

### S4 用户在深层并行 Pause 时取消 Flow

- 参与用户：Flow 编辑用户、Flow 发起用户和 Flow 处理用户
- 开始状态：用户可以定义包含深层显式并行复核 Pause 和后续安全批准 Pause 的多阶段 Flow
- 用户操作：编辑用户定义并发布多阶段 Flow，发起用户启动；处理用户查询到两个复核 Pause 后取消 Flow，再尝试恢复两个原 Pause，并查询 Flow 和后续阶段
- 预期结果：两个恢复请求都被拒绝，不执行汇总、安全批准、发布或通知
- 场景结束：Flow 已取消，没有等待恢复的 Pause

### S5 用户反转两个并行 Pause 的恢复顺序

- 参与用户：Flow 编辑用户、Flow 发起用户和两组 Flow 处理用户
- 开始状态：用户可以定义包含显式并行复核 Pause、汇总和安全批准 Pause 的多阶段 Flow
- 用户操作：编辑用户定义并发布多阶段 Flow，发起用户启动两个实例；一个实例按后端到前端恢复，另一个按前端到后端恢复，每次提交后重新查询并继续恢复安全批准 Pause
- 预期结果：恢复顺序不改变层级、结果归属、汇总次数或最终业务结果
- 场景结束：两个 Flow 运行实例都已完成且没有等待恢复的 Pause

### S6 用户运行调整过 Pause 层级的 Flow

- 参与用户：Flow 编辑用户、Flow 发起用户和 Flow 处理用户
- 开始状态：用户已有多阶段 Flow，并准备只把后端复核 Pause 从第二层移动到准备阶段的直接下一层
- 用户操作：编辑用户修改层级并发布调整后的 Flow，发起用户启动；处理用户查询并恢复所有复核 Pause 和安全批准 Pause，再查询完整历史
- 预期结果：后端复核 Pause 显示新的直接所属层级，前端复核 Pause 层级不变，Flow 仍按真实层级推进且不重复
- 场景结束：调整后的 Flow 已完成，没有等待恢复的 Pause

### S7 用户未添加并行节点时同级步骤保持串行

- 参与用户：Flow 编辑用户、Flow 发起用户和 Flow 处理用户
- 开始状态：用户定义一个普通自动步骤，其直接子步骤依次为确认 Pause 及恢复后的自动收尾，没有添加并行节点
- 用户操作：用户发布并启动 Flow，在确认 Pause 期间查询步骤历史；处理用户恢复确认 Pause 后，发起用户再次查询收尾步骤和最终结果
- 预期结果：Pause 期间只出现确认步骤，后面的同级自动收尾不会提前执行；确认分支完整结束后才执行收尾
- 场景结束：Flow 按定义顺序完成，没有等待恢复的 Pause

## 验证方式

### S1

1. 用户定义并发布包含显式并行复核 Pause、汇总和安全批准 Pause 的多阶段 Flow，再启动运行实例。
2. 用户查询后端复核和前端复核两个 Pause，恢复一个后重新查询剩余 Pause。
3. 用户恢复第二个复核 Pause，查询并确认只出现一次汇总，再查询和恢复安全批准 Pause。
4. 用户查询完整历史，确认十二个业务步骤各执行一次、Flow 已完成且没有等待恢复的 Pause。

### S2

1. 用户定义并发布复核汇总后才进入安全批准 Pause 的多阶段 Flow，再启动并只保留运行编号。
2. 用户第一次查询两个复核 Pause，恢复一个后再次查询。
3. 用户恢复剩余复核 Pause，再次查询此时才出现的安全批准 Pause 并提交结果。
4. 用户确认 Flow 已完成且没有等待恢复的 Pause。

### S3

1. 用户准备只包含一个跨层重复 Pause 标识的 Flow。
2. 用户请求发布并观察明确拒绝。
3. 用户查询正式版本和运行实例数量。
4. 用户确认没有创建任何正式或运行资源。

### S4

1. 用户定义并发布包含深层显式并行复核 Pause 的多阶段 Flow，再启动并查询到两个 Pause。
2. 用户取消 Flow，再尝试恢复两个原 Pause。
3. 用户查询 Flow 状态、汇总及所有后续阶段。
4. 用户确认 Flow 已取消、恢复请求被拒绝且没有等待恢复的 Pause。

### S5

1. 用户定义并发布包含显式并行复核 Pause 和后续安全批准 Pause 的多阶段 Flow，启动两个独立实例并分别查询并行 Pause。
2. 两组用户按相反顺序恢复复核 Pause，每次提交后都重新查询。
3. 两组用户分别查询和恢复后续安全批准 Pause，再查询完整历史。
4. 用户确认两个 Flow 实例都已完成，层级、结果归属和汇总次数一致。

### S6

1. 用户修改后端复核 Pause 的层级并发布调整后的 Flow，再启动运行实例。
2. 用户查询两个复核 Pause，并查看它们各自的直接所属阶段。
3. 用户依次恢复两个复核 Pause，重新查询并恢复后续安全批准 Pause。
4. 用户确认调整后的层级正确、Flow 已完成且没有重复或等待恢复的 Pause。

### S7

1. 用户定义并发布一个没有并行节点、普通父步骤下依次包含确认 Pause 和自动收尾的 Flow，再启动实例。
2. 用户查询到确认 Pause，并查询历史确认自动收尾尚未执行。
3. 用户恢复查询所得 Pause，再重新查询步骤历史和 Flow 结果。
4. 用户确认确认分支结束后才执行自动收尾，Flow 已完成且没有等待恢复的 Pause。
