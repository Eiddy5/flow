# UC-09 用户定义并运行循环流程

## 验证标识

- UC：`UC-09`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`流程编排`
- 需求基线：`用户确认的 Loop 与 LoopUntil 编排规则@2026-08-06`
- 依赖：`UC-06`

## 验证目标

验证用户能够定义按固定次数或本轮结果重复完整流程片段的循环流程，
并通过查询观察每轮顺序、停止条件、成功后的唯一后续结果、失败终态以及
无效定义被拒绝后无正式资源副作用的完整闭环。

## 验证场景

### S1 用户按固定次数完整执行循环体

- 参与用户：Flow 编辑用户和流程发起用户
- 开始状态：本场景尚未创建流程
- 用户操作：编辑用户定义并发布一个循环体包含两个顺序步骤、固定重复三轮且循环后包含一个后续步骤的流程；发起用户启动后查询每轮结果、步骤历史和最终结果
- 预期结果：循环体中的两个步骤按声明顺序完整执行三轮，当前轮完整结束后才开始下一轮，循环后续步骤只执行一次
- 场景结束：流程已完成，没有待处理步骤

### S2 条件在后续轮次满足后结束循环

- 参与用户：Flow 编辑用户和流程发起用户
- 开始状态：本场景尚未创建流程
- 用户操作：编辑用户定义并发布一个最多重复三轮、第一轮结果不满足而第二轮结果满足条件且循环后包含一个后续步骤的流程；发起用户启动后查询每轮结果、后续步骤和最终结果
- 预期结果：每轮完整结束后只根据该轮结果判断，第一轮后继续，第二轮满足条件后停止，不会创建第三轮且循环后续步骤只执行一次
- 场景结束：流程已完成，没有待处理步骤

### S3 条件首次满足时仍完整执行一轮

- 参与用户：Flow 编辑用户和流程发起用户
- 开始状态：本场景尚未创建流程
- 用户操作：编辑用户定义并发布一个第一轮结果即满足条件且循环后包含一个后续步骤的流程；发起用户启动后查询步骤历史、后续步骤和最终结果
- 预期结果：循环体先完整执行一轮再判断条件，条件满足后不会创建第二轮，循环后续步骤只执行一次
- 场景结束：流程已完成，没有待处理步骤

### S4 达到最大轮数仍不满足条件

- 参与用户：Flow 编辑用户和流程发起用户
- 开始状态：本场景尚未创建流程
- 用户操作：编辑用户定义并发布一个最多重复两轮且两轮结果均不满足条件的流程；发起用户启动后查询每轮结果、循环后续步骤和最终结果
- 预期结果：循环体完整执行两轮后停止，流程明确失败，不会创建第三轮也不会执行循环后续步骤
- 场景结束：流程处于失败终态，没有待处理步骤

### S5 循环体失败后停止创建后续轮次

- 参与用户：Flow 编辑用户和流程发起用户
- 开始状态：本场景尚未创建流程
- 用户操作：编辑用户分别定义循环体会失败的固定次数循环和条件循环，并发布两个流程；发起用户分别启动后查询步骤历史、循环后续步骤和最终结果
- 预期结果：两个流程都在循环体失败后停止，均不会创建后续轮次或执行循环后续步骤
- 场景结束：两个流程均处于失败终态，没有待处理步骤

### S6 用户发布无效循环定义

- 参与用户：Flow 编辑用户
- 开始状态：用户准备了空循环体、非正整数轮数、无效条件和错误结果引用的独立草稿
- 用户操作：用户逐一保存并尝试发布这些草稿，每次被拒绝后都查询正式版本和运行流程，最后删除全部草稿
- 预期结果：每次发布都被明确拒绝，不产生正式版本或运行流程
- 场景结束：所有无效草稿已删除，没有遗留正式或运行资源

## 验证方式

### S1

1. 编辑用户定义两个顺序步骤、三轮固定重复和一个循环后续步骤，然后发布流程。
2. 发起用户启动流程，并按轮次查询两个循环体步骤的完成顺序和数量。
3. 用户查询循环后续步骤，确认只有一个完成结果。
4. 用户查询并确认流程已完成、三轮均完整且没有待处理步骤。

### S2

1. 编辑用户定义最多三轮、第一轮不满足而第二轮满足条件的循环和循环后续步骤，然后发布流程。
2. 发起用户启动流程，查询第一轮的完整结果以及随后出现的第二轮。
3. 用户查询第二轮结果、不存在的第三轮以及只执行一次的循环后续步骤。
4. 用户查询并确认流程已完成且没有待处理步骤。

### S3

1. 编辑用户定义第一轮结果即满足条件的循环和循环后续步骤，然后发布流程。
2. 发起用户启动流程，查询第一轮循环体的全部步骤。
3. 用户查询不存在的第二轮和只执行一次的循环后续步骤。
4. 用户查询并确认流程已完成、至少执行了一轮且没有待处理步骤。

### S4

1. 编辑用户定义最多两轮且每轮都不满足条件的循环，并在循环后定义一个对照步骤，然后发布流程。
2. 发起用户启动流程，查询两轮的完整结果。
3. 用户查询不存在的第三轮和未执行的循环后续步骤。
4. 用户查询并确认流程处于失败终态且没有待处理步骤。

### S5

1. 编辑用户分别定义循环体会失败的固定次数循环和条件循环，在两个循环后都设置对照步骤，然后发布两个流程。
2. 发起用户分别启动两个流程，查询循环体的失败结果。
3. 用户查询两个流程都没有后续轮次或循环后续步骤结果。
4. 用户查询并确认两个流程均处于失败终态且没有待处理步骤。

### S6

1. 编辑用户分别保存空循环体、非正整数轮数、无效条件和错误结果引用的独立草稿。
2. 用户逐一尝试发布，并观察每次的明确拒绝结果。
3. 用户查询正式版本和运行流程，确认没有新增资源。
4. 用户删除全部无效草稿，并查询确认没有遗留正式或运行资源。
