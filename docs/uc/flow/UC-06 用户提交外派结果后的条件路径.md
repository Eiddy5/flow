# UC-06 用户提交外派结果后的条件路径

## 验证标识

- UC：`UC-06`
- 状态：`ACCEPTED`
- 领域：`flow`
- 需求基线：`用户确认的外派任务真实用户操作路径@2026-07-28`
- 依赖：`UC-04`

## 验证目标

验证被外派用户查询并完成任务后，流程只执行与本次提交结果匹配的业务路径；没有
匹配、缺失结果、大小写变化、非法条件和两个流程间选择任务都能得到明确且完整的
用户结果。

## 验证场景

### S1 用户选择批准路径

- 参与用户：被外派用户和流程发起用户
- 开始状态：流程等待用户提交批准或拒绝决定
- 用户操作：被外派用户查询任务并提交批准，发起用户查询实际路径和最终结果
- 预期结果：只执行批准处理，不执行拒绝处理
- 场景结束：流程已完成，没有待处理外派任务

### S2 用户选择拒绝路径

- 参与用户：被外派用户和流程发起用户
- 开始状态：流程等待用户提交批准或拒绝决定
- 用户操作：被外派用户查询任务并提交拒绝，发起用户查询实际路径和最终结果
- 预期结果：只执行拒绝处理，不执行批准处理
- 场景结束：流程已完成，没有待处理外派任务

### S3 用户提交没有匹配路径的结果

- 参与用户：被外派用户和流程发起用户
- 开始状态：用户已经查询到自己的待处理外派任务
- 用户操作：用户完成任务并提交未知决定，随后查询流程路径
- 预期结果：批准和拒绝处理都不执行，系统不会擅自选择默认路径
- 场景结束：流程已完成，没有待处理任务

### S4 用户发布包含非法条件的 Flow

- 参与用户：Flow 编辑用户
- 开始状态：待发布 Flow 中有一个语法不完整的条件
- 用户操作：用户请求发布，收到拒绝后查询正式版本和运行流程
- 预期结果：发布被明确拒绝，不产生正式版本或运行流程
- 场景结束：本场景没有创建正式版本或运行资源

### S5 用户提交结果时缺少决定字段

- 参与用户：被外派用户和流程发起用户
- 开始状态：流程等待外派用户提交决定
- 用户操作：被外派用户查询并完成任务，但结果中不包含决定字段，随后查询实际路径
- 预期结果：批准和拒绝处理都不执行，缺失字段不会被解释为任何默认决定
- 场景结束：流程已完成，没有待处理任务

### S6 用户改变决定值的大小写

- 参与用户：被外派用户和流程发起用户
- 开始状态：批准路径只匹配大写的批准值
- 用户操作：被外派用户查询并完成任务，提交小写批准值，随后查询实际路径
- 预期结果：小写值不匹配批准或拒绝处理，系统不执行隐式转换
- 场景结束：流程已完成，没有待处理任务

### S7 用户选择另一个流程中的外派任务

- 参与用户：同一被外派用户
- 开始状态：用户在两个独立流程中各有一个待处理决定任务
- 用户操作：用户查询两个任务，先完成第二个流程的任务，再重新查询并完成第一个
- 预期结果：提交结果只影响所选任务所属流程，不会串用另一个流程的决定或路径
- 场景结束：两个流程都已完成且路径结果互不污染

## 验证方式

### S1

1. 用户启动流程，被外派用户查询自己的决定任务。
2. 被外派用户完成任务并提交批准结果。
3. 发起用户查询批准处理、拒绝处理和流程历史。
4. 用户确认只执行批准处理且流程已完成。

### S2

1. 用户启动独立流程，被外派用户查询自己的决定任务。
2. 被外派用户完成任务并提交拒绝结果。
3. 发起用户查询批准处理、拒绝处理和流程历史。
4. 用户确认只执行拒绝处理且流程已完成。

### S3

1. 被外派用户查询自己的待处理任务。
2. 用户完成任务并提交未知决定。
3. 发起用户查询批准、拒绝处理和完整流程历史。
4. 用户确认两个处理都未执行且流程已完成。

### S4

1. 用户保存一个包含非法条件的 Flow。
2. 用户请求发布并观察明确拒绝。
3. 用户查询正式版本和运行流程数量。
4. 用户确认没有创建正式版本或运行资源。

### S5

1. 被外派用户查询自己的决定任务。
2. 用户完成任务但不提交决定字段。
3. 发起用户查询两个候选处理和最终流程。
4. 用户确认两个处理都未执行且流程已完成。

### S6

1. 被外派用户查询自己的决定任务。
2. 用户完成任务并提交小写批准值。
3. 发起用户查询实际路径和最终结果。
4. 用户确认没有候选处理被执行且流程已完成。

### S7

1. 同一用户启动两个独立流程并查询两个决定任务。
2. 用户根据业务归属先完成第二个流程的任务并提交批准。
3. 用户查询两个流程，确认只有第二个完成，再重新查询并完成第一个任务。
4. 用户查询并确认两个流程都已完成且结果互不污染。
