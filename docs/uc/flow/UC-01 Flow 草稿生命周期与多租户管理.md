# UC-01 Flow 草稿生命周期与多租户管理

## 验证标识

- UC：`UC-01`
- 状态：`ACCEPTED`
- 领域：`flow`
- 需求基线：`用户确认的 Flow 草稿验收需求@2026-07-29`
- 依赖：`无`

## 验证目标

验证用户能够完成 Flow 草稿的创建、查询、修改、重新查询和删除闭环；同时验证
无效草稿、错误查询、删除后操作以及多租户之间的查询、修改、删除和发布互不干扰。

## 验证场景

### S1 用户完成草稿的完整生命周期

- 参与用户：租户 A 的普通用户
- 开始状态：用户尚未创建本场景草稿
- 用户操作：用户创建草稿，按返回的草稿编号查询，修改内容后重新查询，最后删除并再次查询
- 预期结果：草稿编号保持不变，查询内容始终等于用户最后一次保存的内容，删除后不再作为可编辑草稿出现
- 场景结束：本场景草稿已经删除，不遗留可编辑草稿

### S2 用户保存无效草稿并从发布失败中恢复

- 参与用户：租户 A 的普通用户
- 开始状态：用户准备了一份暂时无法成功发布的草稿内容
- 用户操作：用户保存并查询草稿，尝试发布，发布失败后重新查询，再修改草稿并将其删除
- 预期结果：无效内容可以作为草稿保存；发布被明确拒绝且不产生正式版本；原草稿保持可查询和可修改
- 场景结束：用户删除草稿，且没有产生正式版本

### S3 两个租户独立管理内容相同的草稿

- 参与用户：租户 A 用户和租户 B 用户
- 开始状态：两个租户都没有本场景草稿
- 用户操作：两个用户使用相同内容分别创建、查询、修改、重新查询并删除自己的草稿
- 预期结果：两个租户只能看到自己的草稿；任一用户的修改或删除不会改变另一租户的查询结果
- 场景结束：两个租户都删除自己的草稿

### S4 同一租户的不同用户创建和修改草稿

- 参与用户：租户 A 的创建用户和编辑用户
- 开始状态：创建用户尚未创建本场景草稿
- 用户操作：创建用户创建并查询草稿，编辑用户查询并修改，创建用户再次查询修改记录并删除草稿
- 预期结果：草稿仍显示最初创建用户和创建时间，同时显示最后编辑用户、编辑时间和最新内容
- 场景结束：草稿由租户 A 用户删除

### S5 用户查询不存在或错误的草稿编号

- 参与用户：租户 A 的普通用户
- 开始状态：用户已经创建一个对照草稿
- 用户操作：用户查询不存在的编号和填写错误的编号，再重新查询并删除对照草稿
- 预期结果：错误编号不会返回其他草稿或正式 Flow，对照草稿的内容和修改记录保持不变
- 场景结束：对照草稿由用户删除

### S6 缺少租户身份的用户管理草稿

- 参与用户：没有有效租户身份的用户和租户 A 的草稿所有者
- 开始状态：租户 A 已经创建一个对照草稿
- 用户操作：无租户用户尝试创建、查询、修改和删除草稿，随后所有者重新查询并删除对照草稿
- 预期结果：无租户用户的所有操作都被明确拒绝，系统没有创建新草稿，也没有改变对照草稿
- 场景结束：对照草稿由所有者删除，拒绝操作没有遗留资源

### S7 其他租户查询草稿

- 参与用户：租户 A 的草稿所有者和租户 B 用户
- 开始状态：租户 A 已经创建并查询一个草稿
- 用户操作：租户 B 用户使用该草稿编号查询，随后租户 A 所有者重新查询并删除草稿
- 预期结果：租户 B 看不到该草稿，也不能得知草稿内容、修改记录或是否存在；租户 A 的草稿保持不变
- 场景结束：草稿由租户 A 所有者删除

### S8 其他租户修改草稿

- 参与用户：租户 A 的草稿所有者和租户 B 用户
- 开始状态：租户 A 已经创建并查询一个可编辑草稿
- 用户操作：租户 B 用户使用相同草稿编号提交不同内容，租户 A 所有者重新查询并删除草稿
- 预期结果：租户 B 的修改被明确拒绝，草稿内容、创建信息和最后修改信息均保持不变
- 场景结束：草稿由租户 A 所有者删除

### S9 其他租户删除草稿

- 参与用户：租户 A 的草稿所有者和租户 B 用户
- 开始状态：租户 A 拥有一个可编辑草稿
- 用户操作：租户 B 用户请求删除该草稿，租户 A 所有者重新查询、修改并自行删除
- 预期结果：租户 B 的删除被明确拒绝，租户 A 仍能查询和修改自己的草稿
- 场景结束：草稿最终由租户 A 所有者删除

### S10 其他租户发布草稿

- 参与用户：租户 A 的草稿所有者和租户 B 用户
- 开始状态：租户 A 拥有一份可以发布的草稿
- 用户操作：租户 B 用户请求发布该草稿，租户 A 所有者重新查询草稿和正式版本后删除草稿
- 预期结果：租户 B 的发布被明确拒绝，没有为任何租户产生正式版本，租户 A 的草稿保持不变
- 场景结束：草稿由租户 A 所有者删除

### S11 用户在删除后继续修改或发布草稿

- 参与用户：租户 A 的草稿所有者
- 开始状态：用户已经删除本场景草稿
- 用户操作：用户使用原草稿编号尝试修改和发布，然后查询草稿及正式版本
- 预期结果：修改和发布都被明确拒绝，草稿不会恢复或复制，也不会产生正式版本
- 场景结束：原草稿保持已删除状态

### S12 用户混用草稿查询和正式 Flow 查询

- 参与用户：租户 A 的普通用户
- 开始状态：用户已经创建但尚未发布一个草稿
- 用户操作：用户先从正式 Flow 查询中查找该草稿，再从草稿查询中查找并删除
- 预期结果：正式 Flow 查询不会返回草稿，草稿查询能够返回用户保存的原始内容
- 场景结束：用户删除草稿

### S13 用户在草稿内容中填写系统管理字段

- 参与用户：租户 A 的普通用户
- 开始状态：用户准备一份包含自定义编号、正式版本、状态或审计信息的草稿内容
- 用户操作：用户保存并查询草稿，然后尝试发布，发布失败后重新查询并删除
- 预期结果：这些字段只作为草稿原文保存，不能改变系统分配的草稿编号、正式版本、状态或审计信息；发布被明确拒绝
- 场景结束：用户删除草稿，且没有产生正式版本

## 验证方式

### S1

1. 用户创建一份草稿，并从创建结果中取得草稿编号。
2. 用户按编号查询草稿，修改内容后再次查询。
3. 用户比较编号、最新内容和修改记录，并查询确认没有正式版本。
4. 用户删除草稿，再次查询确认它不再可编辑。

### S2

1. 用户提交一份暂时无效的内容并查询保存结果。
2. 用户尝试发布，观察明确的失败结果。
3. 用户重新查询草稿和正式版本，确认原内容仍在且没有正式版本。
4. 用户修改草稿后将其删除，并再次查询确认收尾。

### S3

1. 租户 A 和租户 B 分别创建内容相同的草稿。
2. 两个用户分别查询并修改自己的草稿。
3. 每次修改后，两个用户都重新查询自己的草稿，确认另一租户的操作没有影响。
4. 两个用户分别删除并再次查询自己的草稿。

### S4

1. 创建用户创建并查询草稿，记录创建信息。
2. 编辑用户查询同一草稿并保存新内容。
3. 创建用户重新查询，比较创建信息、最后修改信息和最新内容。
4. 用户删除草稿并查询确认不再可编辑。

### S5

1. 用户创建并查询一个对照草稿。
2. 用户分别查询不存在的编号和填写错误的编号。
3. 用户重新查询对照草稿，确认内容和修改记录没有变化。
4. 用户删除对照草稿并查询确认收尾。

### S6

1. 租户 A 所有者创建并查询一个对照草稿。
2. 无租户用户依次尝试创建、查询、修改和删除。
3. 所有者重新查询对照草稿和正式版本，确认没有变化或新增。
4. 所有者删除对照草稿并查询确认收尾。

### S7

1. 租户 A 所有者创建并查询草稿。
2. 租户 B 用户使用该草稿编号查询。
3. 租户 A 所有者重新查询，确认草稿内容和修改记录不变。
4. 租户 A 所有者删除草稿并查询确认收尾。

### S8

1. 租户 A 所有者创建并查询草稿，记录内容和修改信息。
2. 租户 B 用户使用同一编号提交不同内容。
3. 租户 A 所有者重新查询，确认请求被拒绝且所有信息不变。
4. 租户 A 所有者删除草稿并查询确认收尾。

### S9

1. 租户 A 所有者创建并查询草稿。
2. 租户 B 用户请求删除该草稿。
3. 租户 A 所有者重新查询并修改，确认草稿仍然可用且没有被越权删除。
4. 租户 A 所有者自行删除并查询确认收尾。

### S10

1. 租户 A 所有者创建并查询一份可以发布的草稿。
2. 租户 B 用户使用该编号请求发布。
3. 租户 A 所有者查询草稿和正式版本，确认发布被拒绝且没有副作用。
4. 租户 A 所有者删除草稿并查询确认收尾。

### S11

1. 用户创建、查询并删除一份草稿。
2. 用户使用原编号分别尝试修改和发布。
3. 用户查询草稿和正式版本，确认两个请求都被拒绝且没有新资源。
4. 用户确认原草稿仍处于已删除状态。

### S12

1. 用户创建一份尚未发布的草稿。
2. 用户从正式 Flow 查询中按编号查找，确认没有正式结果。
3. 用户从草稿查询中按编号查找，确认能够看到原始内容。
4. 用户删除草稿并再次查询确认收尾。

### S13

1. 用户创建包含自定义系统字段的草稿并查询原文。
2. 用户尝试发布，观察明确的拒绝结果。
3. 用户重新查询草稿、正式版本和审计信息，确认系统事实没有被改写。
4. 用户删除草稿并查询确认没有遗留正式版本。
