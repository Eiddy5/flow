# UC-01 Flow 草稿生命周期与多租户管理

## 验证标识

- UC：`UC-01`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`流程编排`
- 需求基线：`用户确认的 Flow 草稿、删除及版本化保存语义@2026-09-04`
- 依赖：`无`

## 验证目标

验证用户每次保存 Flow 都会获得系统分配的版本，草稿也不例外；连续保存同一
Flow 会形成递增的新版本，而不会继续使用上一次保存的版本。用户能够完成草稿的
创建、查询、修改、重新查询和删除闭环，同时验证无效草稿、错误查询、删除后操作
以及多租户之间的查询、修改、删除和发布互不干扰。

## 验证场景

### S1 用户完成草稿的版本化生命周期

- 参与用户：租户 A 的普通用户
- 开始状态：租户 A 尚未保存本场景使用的 Flow key
- 用户操作：用户保存首个草稿，按 Flow key 查询并检查返回的版本；修改内容后再次保存并查询最新草稿，最后删除并再次查询
- 预期结果：两次保存都由系统分配版本，第二次保存形成同一租户、同一 Flow key 下的下一个版本而不是继续使用首次版本；新版本内容等于用户最后一次保存的内容，删除后草稿不再可编辑
- 场景结束：本场景草稿已经删除，不遗留可编辑草稿

### S2 用户保存无效草稿并从发布失败中恢复

- 参与用户：租户 A 的普通用户
- 开始状态：用户准备了一份暂时无法成功发布的草稿内容
- 用户操作：用户保存并按 Flow key 查询草稿、检查返回的版本，尝试发布；发布失败后重新查询，修改内容并再次保存，最后删除草稿
- 预期结果：无效内容可以作为带版本的草稿保存；发布被明确拒绝且不产生可运行版本；失败不会改变已保存草稿，再次保存修改内容时形成下一个版本
- 场景结束：用户删除草稿，且没有产生可运行版本

### S3 两个租户独立管理内容相同的草稿

- 参与用户：租户 A 用户和租户 B 用户
- 开始状态：两个租户都没有保存本场景草稿
- 用户操作：两个用户使用相同内容分别保存、查询并删除自己的草稿
- 预期结果：两个租户只能看到自己的草稿，任一用户的保存或删除不会改变另一租户的版本和查询结果
- 场景结束：两个租户都删除自己的草稿

### S4 同一租户的不同用户创建和修改草稿

- 参与用户：租户 A 的创建用户和编辑用户
- 开始状态：创建用户尚未保存本场景使用的 Flow key
- 用户操作：创建用户保存并按 Flow key 查询首个草稿，编辑用户查询后修改内容并再次保存，创建用户查询最新草稿并删除
- 预期结果：编辑用户的保存形成下一个版本；草稿仍显示最初创建用户和创建时间，同时显示最后编辑用户、编辑时间和最新内容
- 场景结束：草稿由租户 A 用户删除

### S5 用户查询不存在或错误的 Flow key

- 参与用户：租户 A 的普通用户
- 开始状态：用户已经保存一个带版本的对照草稿
- 用户操作：用户查询不存在的 Flow key 和填写错误的 Flow key，再按正确 key 重新查询并删除对照草稿
- 预期结果：错误查询不会返回其他草稿或可运行 Flow，对照草稿的内容、版本和修改记录保持不变
- 场景结束：对照草稿由用户删除

### S6 缺少租户身份的用户管理草稿

- 参与用户：没有有效租户身份的用户和租户 A 的草稿所有者
- 开始状态：租户 A 已经保存一个带版本的对照草稿
- 用户操作：无租户用户尝试保存新草稿以及查询、修改和删除对照草稿，随后所有者重新查询并删除对照草稿
- 预期结果：无租户用户的所有操作都被明确拒绝，系统没有创建新版本，也没有改变对照草稿
- 场景结束：对照草稿由所有者删除，拒绝操作没有遗留资源

### S7 其他租户查询草稿

- 参与用户：租户 A 的草稿所有者和租户 B 用户
- 开始状态：租户 A 已经保存并查询一个带版本的草稿，租户 B 没有相同 Flow key 的草稿
- 用户操作：租户 B 用户使用该 Flow key 查询，随后租户 A 所有者按同一 key 重新查询并删除草稿
- 预期结果：租户 B 看不到该草稿，也不能得知草稿内容、版本记录或是否存在；租户 A 的草稿保持不变
- 场景结束：草稿由租户 A 所有者删除

### S8 两个租户独立修改相同 Flow key 的草稿

- 参与用户：租户 A 的草稿所有者和租户 B 用户
- 开始状态：租户 A 和租户 B 已分别使用相同 Flow key 保存自己的草稿
- 用户操作：两个用户按 Flow key 查询各自草稿，分别修改为不同内容并再次保存，然后重新查询并删除自己的草稿
- 预期结果：两个租户的再次保存分别形成自己租户中的下一个版本；任一租户的内容、版本和修改信息都不会被另一租户的同 key 保存改变
- 场景结束：两个租户都删除自己的草稿

### S9 其他租户删除草稿

- 参与用户：租户 A 的草稿所有者和租户 B 用户
- 开始状态：租户 A 拥有一个可编辑的草稿版本
- 用户操作：租户 B 用户请求删除该草稿，租户 A 所有者重新查询、修改并再次保存，最后自行删除草稿
- 预期结果：租户 B 的删除被明确拒绝；租户 A 仍能查询自己的草稿，并在再次保存后获得下一个版本
- 场景结束：草稿最终由租户 A 所有者删除

### S10 其他租户发布草稿

- 参与用户：租户 A 的草稿所有者和租户 B 用户
- 开始状态：租户 A 拥有一份带版本且可以发布的草稿
- 用户操作：租户 B 用户使用该 Flow key 请求发布，租户 A 所有者重新查询草稿和可运行版本后删除草稿
- 预期结果：租户 B 的发布被明确拒绝，没有为任何租户产生可运行版本，租户 A 的草稿版本保持不变
- 场景结束：草稿由租户 A 所有者删除

### S11 用户在删除后继续使用同一 Flow key

- 参与用户：租户 A 的草稿所有者
- 开始状态：用户已经删除本场景 Flow key 对应的当前草稿，并记录删除前返回的版本
- 用户操作：用户按 Flow key 查询并请求发布，确认当前草稿不可用后，以相同 Flow key 保存一个新草稿；用户检查保存结果并按 key 查询最新草稿，最后将其删除
- 预期结果：删除后的当前草稿不可查询或发布；新的保存获得比删除前更高的版本，不会复用已经删除的版本
- 场景结束：新草稿由用户删除

### S12 用户混用草稿查询和可运行 Flow 查询

- 参与用户：租户 A 的普通用户
- 开始状态：用户已经保存一个带版本但尚未发布的草稿
- 用户操作：用户先按 Flow key 和该版本查询已部署 Flow，再按 Flow key 查询最新草稿并删除
- 预期结果：已部署 Flow 的精确查询不会返回未发布草稿，草稿查询能够返回最新草稿的系统版本和原始内容
- 场景结束：用户删除草稿

### S13 用户在草稿内容中填写系统管理字段

- 参与用户：租户 A 的普通用户
- 开始状态：用户准备一份包含自定义系统标识、版本、草稿或删除标记、审计信息的草稿内容
- 用户操作：用户保存并查询草稿，然后尝试发布；发布失败后重新查询并删除
- 预期结果：这些字段只作为草稿原文保存，不能改变系统分配的版本、草稿或删除事实及审计信息；发布被明确拒绝
- 场景结束：用户删除草稿，且没有产生可运行版本

## 验证方式

### S1

1. 用户使用一个尚未保存过的 Flow key 保存草稿，并记录系统返回的版本。
2. 用户按 Flow key 查询草稿，修改内容后再次保存并记录新版本。
3. 用户按 Flow key 查询最新草稿，确认版本递增且内容等于最后一次保存内容。
4. 用户删除草稿，再次查询确认它不再可编辑。

### S2

1. 用户提交一份暂时无效的内容，记录系统返回的草稿版本并查询保存结果。
2. 用户尝试发布，观察明确的失败结果。
3. 用户重新查询确认已保存草稿未被改变，修改内容并再次保存，确认获得下一个版本。
4. 用户删除草稿，并确认没有产生可运行版本。

### S3

1. 租户 A 和租户 B 使用相同内容分别保存草稿并记录各自版本。
2. 两个用户分别按各自 Flow key 查询自己的草稿。
3. 两个用户确认另一租户的保存没有改变自己的版本和内容。
4. 两个用户分别删除自己的草稿并查询确认收尾。

### S4

1. 创建用户保存并按 Flow key 查询首个草稿，记录版本和创建信息。
2. 编辑用户按 Flow key 查询草稿，修改内容并再次保存。
3. 创建用户按 Flow key 查询最新草稿，比较版本、创建信息、最后修改信息和最新内容。
4. 用户删除草稿并查询确认不再可编辑。

### S5

1. 用户保存并查询一个带版本的对照草稿。
2. 用户分别查询不存在的 Flow key 和填写错误的 Flow key。
3. 用户重新查询对照草稿，确认内容、版本和修改记录没有变化。
4. 用户删除对照草稿并查询确认收尾。

### S6

1. 租户 A 所有者保存并查询一个带版本的对照草稿。
2. 无租户用户依次尝试保存新草稿以及查询、修改和删除对照草稿。
3. 所有者重新查询对照草稿和可运行版本，确认没有变化或新增版本。
4. 所有者删除对照草稿并查询确认收尾。

### S7

1. 租户 A 所有者保存并查询一个带版本的草稿。
2. 租户 B 用户使用该 Flow key 查询。
3. 租户 A 所有者重新查询，确认草稿内容、版本和修改记录不变。
4. 租户 A 所有者删除草稿并查询确认收尾。

### S8

1. 租户 A 和租户 B 使用相同 Flow key 分别保存自己的草稿并记录版本。
2. 两个用户按 Flow key 查询各自草稿，修改为不同内容并再次保存。
3. 两个用户重新查询，确认各自获得下一个版本，内容和修改信息没有相互覆盖。
4. 两个用户分别删除自己的草稿并查询确认收尾。

### S9

1. 租户 A 所有者保存并按 Flow key 查询草稿，记录返回的版本。
2. 租户 B 用户请求删除该草稿，租户 A 所有者重新查询确认版本仍然可用。
3. 租户 A 所有者修改内容并再次保存，确认获得下一个版本。
4. 租户 A 所有者自行删除草稿并查询确认收尾。

### S10

1. 租户 A 所有者保存并查询一份带版本且可以发布的草稿。
2. 租户 B 用户使用该 Flow key 请求发布。
3. 租户 A 所有者查询草稿和可运行版本，确认发布被拒绝且没有副作用。
4. 租户 A 所有者删除草稿并查询确认收尾。

### S11

1. 用户保存并按 Flow key 查询草稿，记录版本后将当前草稿删除。
2. 用户按 Flow key 查询当前草稿并请求发布，确认草稿不可查询或发布。
3. 用户以相同 Flow key 保存新草稿，确认系统分配的版本高于删除前版本，再按 key 查询最新草稿。
4. 用户删除新草稿并查询确认收尾。

### S12

1. 用户保存一份尚未发布的草稿，并记录 Flow key 和系统返回的版本。
2. 用户按 Flow key 和该版本查询已部署 Flow，确认没有可运行结果。
3. 用户按 Flow key 查询最新草稿，确认能够看到系统版本和原始内容。
4. 用户删除草稿并再次查询确认收尾。

### S13

1. 用户保存包含自定义系统管理字段的草稿，记录系统返回的版本并查询原文。
2. 用户尝试发布，观察明确的拒绝结果。
3. 用户重新查询草稿、可运行版本和审计信息，确认系统分配的版本及其他事实没有被改写。
4. 用户删除草稿并查询确认没有遗留可运行版本。
