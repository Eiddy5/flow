# UC-04 用户处理外派任务并恢复流程

## 验证标识

- UC：`UC-04`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`任务类型`
- 目标任务类型：`PAUSE`
- 需求基线：`用户确认的外派任务真实用户操作路径@2026-07-28`
- 依赖：`UC-02`、`UC-03`

## 验证目标

验证流程产生外派任务后，被外派用户必须从自己的待办中查询具体任务、提交结果并
推动流程继续；非法输入、重复提交、跨租户、任务替换、取消、恢复失败和系统重启
不会造成越权、重复推进、部分完成或遗留待办。

## 验证场景

### S1 用户查询并完成单个外派任务

- 参与用户：流程发起用户和被外派用户
- 开始状态：用户可以定义并发布包含目标外派任务的标准验证流程
- 验证流程：开始后由前置步骤准备输入，进入唯一目标外派任务，完成后由后置观察步骤读取结果并结束
- 用户操作：发起用户定义、发布并启动流程，查询等待状态；被外派用户查询并完成自己的任务，双方再查询最终结果
- 预期结果：等待状态可以被查询；任务完成后流程继续执行后续步骤
- 场景结束：流程已完成，没有待处理外派任务

### S2 用户提交结果后只恢复对应流程

- 参与用户：流程发起用户和被外派用户
- 开始状态：用户可以定义目标外派任务提交结果后继续处理的标准验证流程
- 验证流程：开始后由前置步骤准备输入，进入唯一目标外派任务，完成后由后置观察步骤读取批准结果并结束
- 用户操作：发起用户定义、发布并启动流程，被外派用户查询唯一待办、提交批准结果，再查询任务结果、流程历史和后续步骤
- 预期结果：提交结果只用于当前任务，原等待步骤和后续自动步骤各执行一次
- 场景结束：流程已完成，没有重复步骤或待处理任务

### S3 非法输入后用户完成正确任务

- 参与用户：被外派用户和流程发起用户
- 开始状态：用户可以定义并发布包含目标外派任务的标准验证流程
- 验证流程：开始后由前置步骤准备输入，进入唯一目标外派任务，合法完成后由后置观察步骤读取结果并结束
- 用户操作：发起用户定义、发布并启动流程；被外派用户查询待办，依次提交不存在编号、空白编号和缺失结果，再重新查询并提交合法结果
- 预期结果：每个非法请求都被明确拒绝，拒绝期间流程和待办不变；合法结果能够继续流程
- 场景结束：流程已完成，没有遗留待处理任务

### S4 用户重复完成已经结束的外派任务

- 参与用户：被外派用户
- 开始状态：用户可以定义并发布包含目标外派任务的标准验证流程
- 验证流程：开始后由前置步骤准备输入，进入唯一目标外派任务，完成后由后置观察步骤读取结果并结束
- 用户操作：用户定义、发布并启动流程，查询并完成目标任务使流程结束，再次提交同一任务结果，然后重新查询任务和流程
- 预期结果：重复提交被明确拒绝，已完成结果、流程历史和步骤数量不变
- 场景结束：流程仍保持已完成

### S5 其他租户查询或完成外派任务

- 参与用户：租户 A 的被外派用户和租户 B 用户
- 开始状态：租户 A 用户可以定义并发布包含目标外派任务的标准验证流程
- 验证流程：开始后由前置步骤准备输入，进入租户 A 的唯一目标外派任务，完成后由后置观察步骤读取结果并结束
- 用户操作：租户 A 用户定义、发布并启动流程；租户 B 查询并尝试完成，租户 A 用户随后重新查询并完成自己的任务
- 预期结果：租户 B 看不到任务且完成请求被拒绝，租户 A 的流程不受影响
- 场景结束：租户 A 的流程已完成

### S6 同一用户在两个流程间选择另一个任务

- 参与用户：同一被外派用户
- 开始状态：用户可以定义并发布包含目标外派任务的标准验证流程
- 验证流程：两个独立流程都在开始后准备输入，分别进入各自唯一目标外派任务，完成后由各自后置观察步骤读取结果并结束
- 用户操作：用户定义并发布验证流程，启动两个独立实例，查询两个任务，先完成第二个流程的任务，再重新查询并完成第一个
- 预期结果：每次提交只推动该任务所属流程，不会把结果写入另一个流程
- 场景结束：两个流程都已完成

### S7 流程取消后用户完成原外派任务

- 参与用户：流程发起用户和被外派用户
- 开始状态：用户可以定义并发布包含目标外派任务的标准验证流程
- 验证流程：开始后由前置步骤准备输入，进入唯一目标外派任务，合法完成后由后置观察步骤读取结果并结束
- 用户操作：发起用户定义、发布并启动流程，被外派用户查询任务后发起用户取消流程；被外派用户使用原查询结果提交完成，再查询流程和待办
- 预期结果：完成请求被明确拒绝，不会恢复流程或创建后续步骤
- 场景结束：流程保持已取消，没有待处理任务

### S8 外派结果提交后的后续处理发生异常

- 参与用户：被外派用户和流程发起用户
- 开始状态：用户可以定义目标外派任务完成后会发生后续异常的标准验证流程
- 验证流程：开始后由前置步骤准备输入，进入唯一目标外派任务，完成后由后置观察步骤读取结果但发生意外异常
- 用户操作：发起用户定义、发布并启动流程，被外派用户查询并提交结果，异常后重新查询，再由发起用户取消流程
- 预期结果：异常明确返回，任务和流程恢复为提交前的等待状态，不产生部分后续结果
- 场景结束：流程已取消，没有待处理任务

### S9 系统重启后用户继续处理外派任务

- 参与用户：流程发起用户和被外派用户
- 开始状态：用户可以定义并发布包含目标外派任务的标准验证流程
- 验证流程：开始后由前置步骤准备输入，进入唯一目标外派任务，完成后由后置观察步骤读取结果并结束
- 用户操作：发起用户定义、发布并启动流程，确认目标任务等待后系统完成重启；被外派用户重新查询任务、完成任务并查询最终流程
- 预期结果：无需使用重启前保存的页面对象或内部信息，也能找到同一任务并继续同一流程
- 场景结束：流程已完成，没有待处理任务

## 验证方式

### S1

1. 用户定义并发布标准验证流程，启动后查询到等待外派处理的状态。
2. 被外派用户从自己的待办中查询具体任务并核对业务信息。
3. 被外派用户完成任务，发起用户重新查询流程和步骤历史。
4. 双方确认流程已完成且待办查询为空。

### S2

1. 用户定义并发布标准验证流程，启动后由被外派用户查询唯一待办。
2. 被外派用户提交批准结果。
3. 用户重新查询任务结果、原等待步骤和后续自动步骤的数量。
4. 用户确认每个步骤只执行一次且流程已完成。

### S3

1. 用户定义并发布标准验证流程，启动后由被外派用户查询自己的待处理任务。
2. 用户依次提交三类非法输入，每次拒绝后都重新查询流程和待办。
3. 用户使用查询所得任务提交合法结果。
4. 用户查询并确认流程已完成且没有遗留待办。

### S4

1. 用户定义并发布标准验证流程，启动后查询并完成目标外派任务，使流程结束。
2. 用户再次提交同一任务结果。
3. 用户观察明确拒绝并重新查询任务、流程和步骤历史。
4. 用户确认流程仍已完成且所有结果和数量不变。

### S5

1. 租户 A 用户定义并发布标准验证流程，启动后查询到自己的待办。
2. 租户 B 用户查询并尝试完成该任务。
3. 租户 A 用户重新查询，确认任务和流程没有变化，再完成任务。
4. 租户 A 用户查询并确认流程已完成。

### S6

1. 用户定义并发布标准验证流程，启动两个独立实例并查询到两个待办。
2. 用户根据业务归属先完成第二个任务。
3. 用户重新查询，确认第一个仍待处理且第二个流程已经完成，再完成第一个。
4. 用户查询并确认两个流程都已完成。

### S7

1. 用户定义并发布标准验证流程，启动后由被外派用户查询并记录自己的待办。
2. 发起用户取消流程。
3. 被外派用户提交原任务完成结果并观察拒绝。
4. 双方查询并确认流程已取消且待办为空。

### S8

1. 用户定义并发布后置观察会发生异常的标准验证流程，启动后由被外派用户查询并尝试完成外派任务。
2. 用户收到后续处理异常。
3. 双方重新查询，确认任务仍待处理且流程没有部分推进。
4. 发起用户取消流程并查询确认没有遗留待办。

### S9

1. 发起用户定义并发布标准验证流程，启动后查询确认外派任务已经产生。
2. 系统完成重启，被外派用户重新登录并从待办中查询任务。
3. 被外派用户完成任务，发起用户重新查询流程和完整历史。
4. 双方确认同一流程已完成且待办为空。
