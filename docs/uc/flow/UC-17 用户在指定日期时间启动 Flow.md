# UC-17 用户在指定日期时间启动 Flow

## 验证标识

- UC：`UC-17`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`流程运行`
- 需求基线：`用户确认的一个或多个指定时间点触发 Flow@2026-09-17`
- 依赖：`UC-01、UC-02`

## 验证目标

用户在 Flow 中列出明确的未来日期时间，系统在每个指定时间点分别启动一次流程；
用户能够逐次查询运行结果，所有指定时间点执行完毕后完成本次计划。

## 验证场景

### S1 在单个指定时间点启动一次流程

- 参与用户：Flow 管理用户
- 开始状态：用户已有一个只有单一正式版本、能自动完成的简单 Flow；该 Flow 仅配置一个日期触发器，列表中只有一个明确的未来时间点；系统持续可用且没有其他启动操作
- 用户操作：用户查询日期配置及已有运行记录，在指定时间前后重新查询运行实例，识别本次新增实例并跟进最终结果
- 预期结果：指定时间前没有新增实例；指定时间到达后自动新增一个实例，该实例按 Flow 定义完整执行，不需要用户手动启动
- 场景结束：本次实例已完成，没有活动步骤；唯一指定时间点已经执行，本次日期列表没有剩余未来时间点

### S2 多个指定时间点分别启动流程

- 参与用户：Flow 管理用户
- 开始状态：用户已有一个只有单一正式版本、能自动完成的简单 Flow；该 Flow 仅配置一个日期触发器，列表中有两个先后不同且明确的未来时间点，间隔足以使第一次运行完成；系统持续可用且没有其他启动操作
- 用户操作：用户查询两个指定时间和已有运行记录，在第一个时间到达后查询本次新增实例并确认完成；第二个时间到达后再次查询新增实例，分别核对两个实例的完整结果
- 预期结果：第一个时间点只新增一个实例，第二个时间点另新增一个不同编号的实例；两次分别启动，不能把两个时间点合并成一次启动，也不能在第一个时间点提前执行第二次；两个实例均按 Flow 定义完整执行
- 场景结束：本次两个实例均已完成，没有活动步骤；两个指定时间点均已执行，本次日期列表没有剩余未来时间点

## 验证方式

### S1

1. 用户通过公开 Flow 查询选择本场景流程，确认日期列表只有一个明确的未来时间点，并记录已有运行实例。
2. 用户在指定时间前查询，确认没有新增实例；时间到达后重新查询，确认只新增一个实例。
3. 用户按新增运行编号查询完整步骤历史和结果。
4. 用户确认本次实例已完成且没有活动步骤，重新核对日期列表没有剩余未来时间点。

### S2

1. 用户通过公开 Flow 查询选择本场景流程，确认日期列表中两个先后不同的未来时间点，并记录已有运行实例。
2. 第一个时间点到达后，用户查询确认只新增一个实例，并在第二个时间点前查询确认该实例已完成且没有提前出现第二个实例。
3. 第二个时间点到达后，用户重新查询确认另新增一个编号不同的实例，分别查询两个实例的完整步骤历史与结果。
4. 用户确认本次两个实例均已完成且没有活动步骤，重新核对日期列表没有剩余未来时间点。
