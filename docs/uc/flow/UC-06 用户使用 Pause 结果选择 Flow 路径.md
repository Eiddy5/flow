# UC-06 用户使用 Pause 结果选择 Flow 路径

## 验证标识

- UC：`UC-06`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`流程编排`
- 需求基线：`用户确认的 Flow Pause 结果条件路径@2026-08-27`
- 依赖：`UC-04`

## 验证目标

验证用户查询处于 Pause 的 Flow 并提交恢复结果后，Flow 只执行与本次 Pause 结果
匹配的业务路径；没有匹配、缺失结果、大小写变化、非法条件以及两个运行实例间
选择 Pause 都能得到明确且完整的用户结果。

## 验证场景

### S1 用户使用 Pause 结果选择批准路径

- 参与用户：Flow 编辑用户、Flow 处理用户和 Flow 发起用户
- 开始状态：用户可以定义根据 Pause 决定选择批准或拒绝处理的条件 Flow
- 用户操作：编辑用户定义并发布条件 Flow，发起用户启动；处理用户查询当前 Pause 并提交批准结果，随后查询实际路径和最终结果
- 预期结果：只执行批准处理，不执行拒绝处理
- 场景结束：Flow 已完成，没有等待恢复的 Pause

### S2 用户使用 Pause 结果选择拒绝路径

- 参与用户：Flow 编辑用户、Flow 处理用户和 Flow 发起用户
- 开始状态：用户可以定义根据 Pause 决定选择批准或拒绝处理的条件 Flow
- 用户操作：编辑用户定义并发布条件 Flow，发起用户启动；处理用户查询当前 Pause 并提交拒绝结果，随后查询实际路径和最终结果
- 预期结果：只执行拒绝处理，不执行批准处理
- 场景结束：Flow 已完成，没有等待恢复的 Pause

### S3 用户提交没有匹配路径的 Pause 结果

- 参与用户：Flow 编辑用户、Flow 处理用户和 Flow 发起用户
- 开始状态：用户可以定义只匹配批准和拒绝结果且没有默认路径的条件 Flow
- 用户操作：编辑用户定义并发布条件 Flow，发起用户启动；处理用户查询当前 Pause 并提交未知决定，随后查询 Flow 路径
- 预期结果：批准和拒绝处理都不执行，系统不会擅自选择默认路径
- 场景结束：Flow 已完成，没有等待恢复的 Pause

### S4 用户发布包含非法条件的 Flow

- 参与用户：Flow 编辑用户
- 开始状态：待发布 Flow 中有一个语法不完整的条件
- 用户操作：用户请求发布，收到拒绝后查询正式版本和运行实例
- 预期结果：发布被明确拒绝，不产生正式版本或运行实例
- 场景结束：本场景没有创建正式版本或运行资源

### S5 用户提交 Pause 结果时缺少决定字段

- 参与用户：Flow 编辑用户、Flow 处理用户和 Flow 发起用户
- 开始状态：用户可以定义根据决定字段选择批准或拒绝处理的条件 Flow
- 用户操作：编辑用户定义并发布条件 Flow，发起用户启动；处理用户查询当前 Pause 并提交不包含决定字段的结果，随后查询实际路径
- 预期结果：批准和拒绝处理都不执行，缺失字段不会被解释为任何默认决定
- 场景结束：Flow 已完成，没有等待恢复的 Pause

### S6 用户改变 Pause 决定值的大小写

- 参与用户：Flow 编辑用户、Flow 处理用户和 Flow 发起用户
- 开始状态：用户可以定义批准路径只匹配大写批准值的条件 Flow
- 用户操作：编辑用户定义并发布条件 Flow，发起用户启动；处理用户查询当前 Pause 并提交小写批准值，随后查询实际路径
- 预期结果：小写值不匹配批准或拒绝处理，系统不执行隐式转换
- 场景结束：Flow 已完成，没有等待恢复的 Pause

### S7 用户选择另一个 Flow 运行实例中的 Pause

- 参与用户：Flow 编辑用户、Flow 发起用户和同一 Flow 处理用户
- 开始状态：用户可以定义根据 Pause 决定选择业务路径的条件 Flow
- 用户操作：编辑用户定义并发布条件 Flow，发起用户启动两个运行实例；处理用户查询两个实例及其 Pause，先恢复第二个实例，再重新查询并恢复第一个实例
- 预期结果：提交结果只影响所选 Pause 所属的 Flow 实例，不会串用另一个实例的决定或路径
- 场景结束：两个 Flow 运行实例都已完成且路径结果互不污染

## 验证方式

### S1

1. 用户定义并发布批准或拒绝条件 Flow，再启动运行实例并查询当前 Pause。
2. 用户向查询所得 Pause 提交批准结果。
3. 用户查询批准处理、拒绝处理和 Flow 历史。
4. 用户确认只执行批准处理且 Flow 已完成。

### S2

1. 用户定义并发布批准或拒绝条件 Flow，再启动独立实例并查询当前 Pause。
2. 用户向查询所得 Pause 提交拒绝结果。
3. 用户查询批准处理、拒绝处理和 Flow 历史。
4. 用户确认只执行拒绝处理且 Flow 已完成。

### S3

1. 用户定义并发布没有默认路径的条件 Flow，再启动并查询当前 Pause。
2. 用户向查询所得 Pause 提交未知决定。
3. 用户查询批准、拒绝处理和完整 Flow 历史。
4. 用户确认两个处理都未执行且 Flow 已完成。

### S4

1. 用户保存一个包含非法条件的 Flow。
2. 用户请求发布并观察明确拒绝。
3. 用户查询正式版本和运行实例数量。
4. 用户确认没有创建正式版本或运行资源。

### S5

1. 用户定义并发布依赖决定字段的条件 Flow，再启动并查询当前 Pause。
2. 用户向查询所得 Pause 提交不包含决定字段的结果。
3. 用户查询两个候选处理和最终 Flow。
4. 用户确认两个处理都未执行且 Flow 已完成。

### S6

1. 用户定义并发布大小写精确匹配的条件 Flow，再启动并查询当前 Pause。
2. 用户向查询所得 Pause 提交小写批准值。
3. 用户查询实际路径和最终结果。
4. 用户确认没有候选处理被执行且 Flow 已完成。

### S7

1. 用户定义并发布条件 Flow，启动两个独立实例并查询各自的 Pause。
2. 用户根据运行实例先恢复第二个 Flow 的 Pause 并提交批准结果。
3. 用户查询两个实例，确认只有第二个完成，再重新查询并恢复第一个实例。
4. 用户确认两个 Flow 运行实例都已完成且结果互不污染。
