# UC-10 用户处理包含嵌套编排的审批 Flow

## 验证标识

- UC：`UC-10`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`流程编排`
- 需求基线：`当前对话确认@2026-08-28`
- 依赖：`UC-04`、`UC-05`、`UC-06`、`UC-07`、`UC-09`

## 验证目标

验证用户能够定义并运行包含一到两层嵌套以及审批中常见三层嵌套的 Flow：外层顺序
编排正确解锁条件分支、并行会签或条件循环，嵌套审批按各自顺序推进，只有满足嵌套
收敛条件后才进入后续审批、记录、发布或通知；驳回、取消和达到最大轮数时，未解锁
的审批及后续步骤不会被执行。

## 验证场景

### S1 多级串签审批通过

- 参与用户：Flow 编辑用户、流程发起用户、初审用户、财务审批用户和法务审批用户
- 开始状态：用户可以定义并发布一个外层按顺序推进的审批 Flow，先进行初审；初审通过后进入通过条件分支，分支内依次进行财务审批和法务审批，全部完成后记录审批结果并结束
- 用户操作：用户定义、发布并启动 Flow；初审用户查询并通过初审；财务审批用户查询新出现的财务审批并通过；法务审批用户查询新出现的法务审批并通过；用户查询审批记录和 Flow 最终结果
- 预期结果：初审通过前不会出现财务或法务审批；财务审批完成前不会出现法务审批；全部审批完成前不会执行记录和结束动作；财务审批、法务审批、记录和结束动作均只执行一次
- 场景结束：Flow 已以审批通过的完成终态结束，没有未处理审批

### S2 初审驳回后短路结束

- 参与用户：Flow 编辑用户、流程发起用户、初审用户、财务审批用户和法务审批用户
- 开始状态：用户可以定义并发布与多级串签相同的审批 Flow，其中初审驳回后进入驳回处理并结束，初审通过后才会进入财务和法务审批
- 用户操作：用户定义、发布并启动 Flow；初审用户查询并驳回初审；用户重新查询驳回处理、财务审批、法务审批和 Flow 最终结果
- 预期结果：初审驳回后只出现驳回处理并结束；财务审批、法务审批和通过后的记录动作均不出现，Flow 不继续后续审批
- 场景结束：Flow 已以驳回处理的完成终态结束，没有未处理审批或通过分支步骤

### S3 并行会签后进入终审

- 参与用户：Flow 编辑用户、流程发起用户、第一会签分支负责人、第一会签分支复核人、第二会签分支负责人、第二会签分支复核人和总负责人
- 开始状态：用户可以定义并发布一个外层按顺序推进的审批 Flow，其中包含并行会签阶段；两个会签分支分别按顺序进行负责人审批和复核审批，全部会签完成后进入总负责人终审，再执行后续汇总和结束步骤
- 用户操作：用户定义、发布并启动 Flow；分别查询两个会签分支；完成一个分支的负责人审批并确认该分支的复核审批随后出现，再完成该复核；以相同方式完成另一分支；用户查询总负责人终审、后续汇总和最终结果并完成终审
- 预期结果：两个会签分支可以分别推进，但每个分支的复核审批都只能在本分支负责人审批完成后出现；两个分支的负责人审批和复核审批全部完成前不会出现总负责人终审；总负责人终审只出现并执行一次，之后才执行一次汇总和结束步骤
- 场景结束：Flow 已完成，没有未处理的会签审批或终审

### S4 并行会签中途取消

- 参与用户：Flow 编辑用户、流程发起用户、会签分支负责人、会签分支复核人和总负责人
- 开始状态：用户可以定义并发布包含两个并行会签分支的审批 Flow，每个分支都按顺序包含负责人审批和复核审批，全部会签完成后才进入总负责人终审及汇总、发布、通知步骤
- 用户操作：用户定义、发布并启动 Flow；完成一个会签分支的负责人审批，使该分支进入复核审批，随后取消 Flow；用户重新查询未完成审批、总负责人终审、汇总、发布、通知和 Flow 结果，并尝试继续未完成审批
- 预期结果：取消后未完成的会签审批不能继续；总负责人终审以及后续汇总、发布和通知都不出现，已完成的部分审批不会重新触发其他分支或后续步骤
- 场景结束：Flow 已取消，没有仍可处理的会签审批或后续步骤

### S5 补充材料后重新审批

- 参与用户：Flow 编辑用户、流程发起用户、材料提交用户、材料复核用户和最终审批用户
- 开始状态：用户可以定义并发布一个外层按顺序推进的审批 Flow，其中包含条件循环；每一轮在循环内依次完成补充材料和材料复核，材料复核通过后才进入最终审批
- 用户操作：用户定义、发布并启动 Flow；材料提交用户完成第一轮补充材料，材料复核用户复核后确认仍需补充；用户查询并确认进入下一轮，再完成第二轮补充材料和材料复核并确认通过；最终审批用户查询新出现的最终审批并完成审批，用户查询 Flow 最终结果
- 预期结果：每一轮都先完成补充材料再进行材料复核；第一轮需要补充时才创建下一轮；第二轮材料复核通过前不会出现最终审批；最终审批只在循环满足通过条件后出现并执行一次
- 场景结束：Flow 已以审批通过的完成终态结束，没有未完成轮次或审批

### S6 补充材料超过最大次数

- 参与用户：Flow 编辑用户、流程发起用户、材料提交用户和材料复核用户
- 开始状态：用户可以定义并发布一个外层按顺序推进的审批 Flow，其中包含有最大轮数限制的条件循环；每一轮依次完成补充材料和材料复核，所有轮次都可能未通过，循环后才有最终审批和后续步骤
- 用户操作：用户定义、发布并启动 Flow；逐轮完成补充材料并提交材料复核结果，直至每一轮均未通过并达到最大轮数；用户在每轮后查询下一轮、最终审批及后续步骤，再查询 Flow 最终结果
- 预期结果：每一轮都先完成补充材料再进行材料复核；达到最大轮数后 Flow 明确失败，不创建下一轮；最终审批以及后续步骤都不出现
- 场景结束：Flow 已处于失败终态，没有未完成轮次、最终审批或后续步骤

## 验证方式

### S1

1. 用户定义并发布外层顺序、初审、通过条件分支、财务审批、法务审批、记录和结束步骤组成的审批 Flow，并启动运行实例。
2. 用户查询并通过初审，确认财务审批出现而法务审批、记录和结束动作尚未出现。
3. 用户通过财务审批后重新查询，确认法务审批出现；通过法务审批后再次查询完整审批记录和 Flow 历史。
4. 用户确认所有审批按顺序各执行一次，记录和结束动作在最后执行一次，Flow 已完成且没有未处理审批。

### S2

1. 用户定义并发布初审驳回后进入驳回处理的嵌套审批 Flow，并启动运行实例。
2. 用户查询并驳回初审。
3. 用户重新查询驳回处理、财务审批、法务审批、通过后的记录动作和 Flow 历史。
4. 用户确认只执行驳回处理并结束，财务审批、法务审批和通过分支均未出现，Flow 已完成且没有未处理审批。

### S3

1. 用户定义并发布外层顺序、并行会签、两个“负责人审批后复核审批”的会签分支、总负责人终审、汇总和结束步骤组成的审批 Flow，并启动运行实例。
2. 用户查询两个会签分支，完成一个分支的负责人审批，确认只有该分支的复核审批出现；完成该复核后再完成另一分支的负责人审批和复核审批。
3. 用户在每次审批后查询，确认两个分支全部完成前总负责人终审没有出现；全部完成后查询并完成只出现一次的总负责人终审。
4. 用户查询汇总、结束步骤和完整 Flow 历史，确认汇总和结束步骤各执行一次，Flow 已完成且没有未处理审批。

### S4

1. 用户定义并发布两个并行会签分支、每个分支均含负责人审批和复核审批、终审及汇总发布通知步骤的审批 Flow，并启动运行实例。
2. 用户完成一个会签分支的负责人审批，确认该分支进入复核审批且其他会签分支仍未完成。
3. 用户取消 Flow，再查询未完成审批、总负责人终审、汇总、发布、通知和 Flow 历史，并尝试处理原查询所得未完成审批。
4. 用户确认未完成审批被禁止继续，Flow 已取消，终审和全部后续汇总、发布、通知均未出现。

### S5

1. 用户定义并发布外层顺序、条件循环、每轮“补充材料后材料复核”、最终审批和结束步骤组成的审批 Flow，并启动运行实例。
2. 用户完成第一轮补充材料和材料复核，确认复核结果为需要补充；重新查询并确认下一轮出现，最终审批尚未出现。
3. 用户完成第二轮补充材料和材料复核并确认通过，再查询新出现的最终审批并完成它。
4. 用户查询完整 Flow 历史，确认每轮内部顺序正确，最终审批只执行一次，Flow 已完成且没有未完成轮次或审批。

### S6

1. 用户定义并发布外层顺序、有限次数条件循环、每轮“补充材料后材料复核”、最终审批和后续步骤组成的审批 Flow，并启动运行实例。
2. 用户逐轮完成补充材料和材料复核，每轮均提交未通过结果，并在每轮后查询下一轮是否出现。
3. 用户达到最大轮数后查询下一轮、最终审批和后续步骤，再查询 Flow 最终结果。
4. 用户确认没有创建下一轮，最终审批和后续步骤均未出现，Flow 已明确失败且没有未完成轮次或审批。
