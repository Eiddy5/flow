# UC-10 用户处理包含嵌套编排的审批 Flow

## 验证标识

- UC：`UC-10`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`流程编排`
- 需求基线：`嵌套审批编排及跨条件退回规则确认@2026-09-07`
- 依赖：`UC-04`、`UC-05`、`UC-06`、`UC-07`、`UC-09`

## 验证目标

验证用户能够定义并运行包含一到两层嵌套以及审批中常见三层嵌套的 Flow：外层顺序
编排正确解锁条件分支、并行会签或条件循环，嵌套审批按各自顺序推进，只有满足嵌套
收敛条件后才进入后续审批、记录、发布或通知；驳回、取消和达到最大轮数时，未解锁
的审批及后续步骤不会被执行。审批 Pause 可以退回到实际路径上选定的上一审批 Pause，
条件和自动通知步骤不阻断退回，支持同分支、跨条件层级及并行汇合后的指定分支；
未受影响分支仍然有效，旧审批不能继续处理，重新审批后能够正常完成。

## 验证场景

### S1 多级串签审批通过

- 参与用户：Flow 编辑用户、流程发起用户、初审用户、财务审批用户和法务审批用户
- 开始状态：用户可以定义并发布一个外层按顺序推进的审批 Flow，先进行初审；初审通过后进入通过条件分支，分支内依次进行财务审批和法务审批，全部完成后记录审批结果并结束
- 用户操作：用户定义、发布并启动 Flow；初审用户查询并通过初审；财务审批用户查询新出现的财务审批并通过；法务审批用户查询新出现的法务审批并通过；用户查询审批记录和 Flow 最终结果
- 预期结果：初审通过前不会出现财务或法务审批；财务审批完成前不会出现法务审批；全部审批完成前不会执行记录和结束动作；财务审批、法务审批、记录和结束动作均只执行一次
- 场景结束：Flow 已以审批通过的完成终态结束，没有未处理审批

### S2 初审驳回后短路结束

- 参与用户：Flow 编辑用户、流程发起用户、初审用户、财务审批用户和法务审批用户
- 开始状态：用户可以定义并发布与多级串签相同的审批 Flow，其中初审驳回后进入驳回处理并结束，初审通过后才会进入财务和法务审批
- 用户操作：用户定义、发布并启动 Flow；初审用户查询并驳回初审；用户重新查询驳回处理、财务审批、法务审批和 Flow 最终结果
- 预期结果：初审驳回后只出现驳回处理并结束；财务审批、法务审批和通过后的记录动作均不出现，Flow 不继续后续审批
- 场景结束：Flow 已以驳回处理的完成终态结束，没有未处理审批或通过分支步骤

### S3 并行会签后进入终审

- 参与用户：Flow 编辑用户、流程发起用户、第一会签分支负责人、第一会签分支复核人、第二会签分支负责人、第二会签分支复核人和总负责人
- 开始状态：用户可以定义并发布一个外层按顺序推进的审批 Flow，其中包含并行会签阶段；两个会签分支分别按顺序进行负责人审批和复核审批，全部会签完成后进入总负责人终审，再执行后续汇总和结束步骤
- 用户操作：用户定义、发布并启动 Flow；分别查询两个会签分支；完成一个分支的负责人审批并确认该分支的复核审批随后出现，再完成该复核；以相同方式完成另一分支；用户查询总负责人终审、后续汇总和最终结果并完成终审
- 预期结果：两个会签分支可以分别推进，但每个分支的复核审批都只能在本分支负责人审批完成后出现；两个分支的负责人审批和复核审批全部完成前不会出现总负责人终审；总负责人终审只出现并执行一次，之后才执行一次汇总和结束步骤
- 场景结束：Flow 已完成，没有未处理的会签审批或终审

### S4 并行会签中途取消

- 参与用户：Flow 编辑用户、流程发起用户、会签分支负责人、会签分支复核人和总负责人
- 开始状态：用户可以定义并发布包含两个并行会签分支的审批 Flow，每个分支都按顺序包含负责人审批和复核审批，全部会签完成后才进入总负责人终审及汇总、发布、通知步骤
- 用户操作：用户定义、发布并启动 Flow；完成一个会签分支的负责人审批，使该分支进入复核审批，随后取消 Flow；用户重新查询未完成审批、总负责人终审、汇总、发布、通知和 Flow 结果，并尝试继续未完成审批
- 预期结果：取消后未完成的会签审批不能继续；总负责人终审以及后续汇总、发布和通知都不出现，已完成的部分审批不会重新触发其他分支或后续步骤
- 场景结束：Flow 已取消，没有仍可处理的会签审批或后续步骤

### S5 补充材料后重新审批

- 参与用户：Flow 编辑用户、流程发起用户、材料提交用户、材料复核用户和最终审批用户
- 开始状态：用户可以定义并发布一个外层按顺序推进的审批 Flow，其中包含条件循环；每一轮在循环内依次完成补充材料和材料复核，材料复核通过后才进入最终审批
- 用户操作：用户定义、发布并启动 Flow；材料提交用户完成第一轮补充材料，材料复核用户复核后确认仍需补充；用户查询并确认进入下一轮，再完成第二轮补充材料和材料复核并确认通过；最终审批用户查询新出现的最终审批并完成审批，用户查询 Flow 最终结果
- 预期结果：每一轮都先完成补充材料再进行材料复核；第一轮需要补充时才创建下一轮；第二轮材料复核通过前不会出现最终审批；最终审批只在循环满足通过条件后出现并执行一次
- 场景结束：Flow 已以审批通过的完成终态结束，没有未完成轮次或审批

### S6 补充材料超过最大次数

- 参与用户：Flow 编辑用户、流程发起用户、材料提交用户和材料复核用户
- 开始状态：用户可以定义并发布一个外层按顺序推进的审批 Flow，其中包含有最大轮数限制的条件循环；每一轮依次完成补充材料和材料复核，所有轮次都可能未通过，循环后才有最终审批和后续步骤
- 用户操作：用户定义、发布并启动 Flow；逐轮完成补充材料并提交材料复核结果，直至每一轮均未通过并达到最大轮数；用户在每轮后查询下一轮、最终审批及后续步骤，再查询 Flow 最终结果
- 预期结果：每一轮都先完成补充材料再进行材料复核；达到最大轮数后 Flow 明确失败，不创建下一轮；最终审批以及后续步骤都不出现
- 场景结束：Flow 已处于失败终态，没有未完成轮次、最终审批或后续步骤

### S7 同一条件分支内退回上一审批

- 参与用户：Flow 编辑用户、流程发起用户、初审用户和复核用户
- 开始状态：用户可以定义并发布按采购金额选择分支的 Flow；命中分支依次包含初审 Pause、自动通知和复核 Pause，分支汇合后记录结果并结束
- 用户操作：用户定义、发布并启动 Flow；初审用户查询并完成初审，复核用户查询当前复核和已完成初审，填写原因并退回初审；用户重新查询新的初审，尝试恢复旧复核和再次从旧复核退回，再依次查询并完成新的初审和复核，最后查询 Flow 结果
- 预期结果：条件内的复核可以退回同分支初审，自动通知不阻断退回；初审、通知和复核按顺序重新执行，未命中分支不执行；旧复核的恢复和再次退回均被明确拒绝，新初审及当前路径不受拒绝请求影响；后续记录只在新的复核通过后执行一次，并使用重新审批的结果
- 场景结束：Flow 已完成，历史保留本次退回原因和旧审批记录，没有仍可处理的旧审批或等待恢复的 Pause

### S8 条件分支首个审批退回分流前审批

- 参与用户：Flow 编辑用户、流程发起用户、初审用户和分支审批用户
- 开始状态：用户可以定义并发布先初审、再按固定申请金额选择条件分支的 Flow；初审与分支审批之间有自动通知，命中分支只有一个审批 Pause，汇合后记录结果并结束
- 用户操作：用户定义、发布并启动 Flow；查询并完成初审，查询命中分支当前审批及分流前已完成的初审，填写原因并退回初审；用户重新查询并完成新初审，再查询并完成重新出现的分支审批，最后查询 Flow 历史和最终结果
- 预期结果：分支首个审批可以跨过条件和通知退回分流前初审；目标初审之前的步骤不重复，重新初审完成前分支审批不可处理；申请金额不变时仍只进入原命中分支，未命中分支的审批不执行；后续记录使用重新审批结果并只在分支完成后执行一次
- 场景结束：Flow 已完成，退回前后的审批历史可查询，没有等待恢复的 Pause

### S9 条件汇合后退回实际命中分支的最后审批

- 参与用户：Flow 编辑用户、流程发起用户、条件分支审批用户和终审用户
- 开始状态：用户可以定义并发布包含金额较大和金额较小两个互斥分支的 Flow；每个分支各有一个审批 Pause，分支汇合后先自动通知、再终审，最终记录结果并结束
- 用户操作：用户定义并发布 Flow，分别以命中不同分支的金额启动两个独立实例；每个实例都查询并完成本次分支审批，终审用户重新查询当前终审和该实例的审批历史，填写原因并退回本次分支审批；用户分别查询并完成新的分支审批和终审，再查询两个实例的最终结果
- 预期结果：每次退回都重新进入本次实际命中分支，汇合与通知不阻断退回；未命中分支没有可供退回的审批运行记录，也不会因退回产生审批；两个实例互不影响；目标分支之前的步骤不重复，新分支审批完成后才出现新的终审，最终结果使用各自重新审批的结果
- 场景结束：两个 Flow 实例均已完成，各自只执行一次最终记录，没有等待恢复的 Pause

### S10 深层条件内审批退回外层分支审批

- 参与用户：Flow 编辑用户、流程发起用户、外层审批用户和深层审批用户
- 开始状态：用户可以定义并发布四层条件嵌套的 Flow；最外层命中分支先进行外层审批 Pause，再通过三层条件和自动通知进入深层审批 Pause，深层分支结束后有外层记录和最终结束步骤，各层都有未命中的其他分支
- 用户操作：用户定义、发布并启动 Flow；查询并完成外层审批，查询深层当前审批和已完成外层审批，填写原因并退回外层审批；用户重新查询并完成新的外层审批，沿本次命中路径重新查询并完成深层审批，最后查询各层路径、记录和 Flow 结果
- 预期结果：退回不因条件嵌套层数受阻，外层审批重新出现后才按原条件路径再次到达深层审批；各层未命中分支不执行，目标之前的步骤不重复；深层新审批完成前外层记录和最终结束步骤不执行，完成后各执行一次并采用最新审批结果
- 场景结束：Flow 已完成，所有条件层级均已结束，没有等待恢复的 Pause

### S11 并行分支内退回不使其他等待分支失效

- 参与用户：Flow 编辑用户、流程发起用户、第一分支初审用户、第一分支复核用户和第二分支审批用户
- 开始状态：用户可以定义并发布两个并行分支的 Flow；第一分支在命中条件内依次包含初审和复核两个 Pause，第二分支只有一个审批 Pause，两分支完成后汇总并结束
- 用户操作：用户定义、发布并启动 Flow；完成第一分支初审，重新查询第一分支复核和第二分支审批；从第一分支复核填写原因并退回本分支初审，查询第一分支新初审和第二分支原审批；第二分支用户完成查询所得原审批，再依次查询并完成第一分支新初审和新复核，最后查询汇总和 Flow 结果
- 预期结果：退回只重做第一分支初审至复核片段；第二分支原审批仍有效且可以完成，其运行记录和结果不会被替换或重复；第一分支重新审批完成前不能提前汇总；最终汇总使用第一分支最新结果和第二分支原有效结果，且只执行一次
- 场景结束：Flow 已完成，没有等待恢复的 Pause，第二分支没有重复审批记录

### S12 并行汇合后只退回用户选定的上一分支审批

- 参与用户：Flow 编辑用户、流程发起用户、两个并行分支审批用户和终审用户
- 开始状态：用户可以定义并发布两个独立并行审批 Pause、汇合后终审及最终记录的 Flow；两个并行审批都作为终审的合法退回目标
- 用户操作：用户定义、发布并启动 Flow；查询并先完成第一分支审批，再查询并完成第二分支审批；终审用户重新查询两个已完成分支审批，从当前终审选择较早完成的第一分支审批并填写原因退回；用户查询并完成第一分支新审批，再查询并完成重新出现的终审，最后查询完整历史和最终结果
- 预期结果：退回使用用户选定的第一分支审批，不因第二分支更晚完成而改选目标；每次只重新审批一个选定分支，第二分支已完成记录和结果仍有效且不重复；第一分支新审批完成前不会出现新的终审；新终审可以结合第一分支新结果和第二分支原结果正常完成，最终记录只执行一次
- 场景结束：Flow 已完成，没有等待恢复的 Pause，也没有第二分支重复审批

### S13 跨条件退回后再次退回使用当前有效审批

- 参与用户：Flow 编辑用户、流程发起用户、分支审批用户和终审用户
- 开始状态：用户可以定义并发布两层条件嵌套的 Flow；命中的内层分支有一个审批 Pause，条件汇合后有终审 Pause，最后记录最新审批结果并结束
- 用户操作：用户定义、发布并启动 Flow；查询并完成分支审批，从查询所得终审填写第一个原因退回分支审批；查询并完成新的分支审批，在重新出现的终审上先尝试选择已被第一次退回替代的旧分支审批，再重新查询并选择当前已完成的分支审批，填写第二个原因退回；用户逐步查询并完成最新分支审批和终审，最后查询全部退回历史与最终结果
- 预期结果：旧分支审批不能作为本次退回目标，拒绝后当前终审和有效路径不变；第二次合法退回使用当前终审和当前已完成的分支审批，只重做当前有效路径的相应片段；两次退回的原因及各次审批历史均保留，旧审批不能重新成为可处理步骤；最终记录使用最新一轮审批结果，未命中分支不执行
- 场景结束：Flow 已完成，历史保留两次退回，没有活动退回片段或等待恢复的 Pause

## 验证方式

### S1

1. 用户定义并发布外层顺序、初审、通过条件分支、财务审批、法务审批、记录和结束步骤组成的审批 Flow，并启动运行实例。
2. 用户查询并通过初审，确认财务审批出现而法务审批、记录和结束动作尚未出现。
3. 用户通过财务审批后重新查询，确认法务审批出现；通过法务审批后再次查询完整审批记录和 Flow 历史。
4. 用户确认所有审批按顺序各执行一次，记录和结束动作在最后执行一次，Flow 已完成且没有未处理审批。

### S2

1. 用户定义并发布初审驳回后进入驳回处理的嵌套审批 Flow，并启动运行实例。
2. 用户查询并驳回初审。
3. 用户重新查询驳回处理、财务审批、法务审批、通过后的记录动作和 Flow 历史。
4. 用户确认只执行驳回处理并结束，财务审批、法务审批和通过分支均未出现，Flow 已完成且没有未处理审批。

### S3

1. 用户定义并发布外层顺序、并行会签、两个“负责人审批后复核审批”的会签分支、总负责人终审、汇总和结束步骤组成的审批 Flow，并启动运行实例。
2. 用户查询两个会签分支，完成一个分支的负责人审批，确认只有该分支的复核审批出现；完成该复核后再完成另一分支的负责人审批和复核审批。
3. 用户在每次审批后查询，确认两个分支全部完成前总负责人终审没有出现；全部完成后查询并完成只出现一次的总负责人终审。
4. 用户查询汇总、结束步骤和完整 Flow 历史，确认汇总和结束步骤各执行一次，Flow 已完成且没有未处理审批。

### S4

1. 用户定义并发布两个并行会签分支、每个分支均含负责人审批和复核审批、终审及汇总发布通知步骤的审批 Flow，并启动运行实例。
2. 用户完成一个会签分支的负责人审批，确认该分支进入复核审批且其他会签分支仍未完成。

### S5

### S6

### S7

### S9
