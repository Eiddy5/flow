# UC-07 用户处理多阶段外派流程

## 验证标识

- UC：`UC-07`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`流程编排`
- 需求基线：`用户确认的默认串行与显式并行规则@2026-07-30`
- 依赖：`UC-04`、`UC-05`、`UC-06`

## 验证目标

验证包含多层串行业务步骤、显式并行复核、汇总和后续安全批准的长流程能够形成
完整用户旅程：普通同级步骤按声明顺序推进，只有用户添加的并行节点才同时产生
分支；用户每次只处理当前查询到的任务，直至流程结束。

## 验证场景

### S1 用户完成完整多阶段流程

- 参与用户：Flow 编辑用户、流程发起用户和各阶段被外派用户
- 开始状态：用户可以定义包含准备、显式并行复核节点、汇总、安全批准、发布和通知的多阶段流程
- 用户操作：编辑用户定义并发布多阶段流程，发起用户启动；被外派用户依次查询并完成显式并行节点下的两个复核和之后出现的安全批准任务
- 预期结果：复核结果归属正确，只汇总一次，安全批准只在复核汇总后出现，全部十二个业务步骤各执行一次
- 场景结束：流程已完成，没有待处理外派任务

### S2 用户在每个等待阶段重新查询

- 参与用户：Flow 编辑用户、被外派用户和流程发起用户
- 开始状态：用户可以定义显式并行复核节点，复核汇总完成后才产生安全批准任务
- 用户操作：编辑用户定义并发布多阶段流程，发起用户启动并只保留运行编号；被外派用户查询两个复核任务，完成一个后重新查询，完成另一个后再查询新出现的安全批准并完成
- 预期结果：每次查询只显示当前真实可处理任务，未来阶段任务不会提前出现
- 场景结束：流程已完成，最后一次待办查询为空

### S3 用户发布包含跨层重复步骤标识的 Flow

- 参与用户：Flow 编辑用户
- 开始状态：不同层级中出现了重复的业务步骤标识
- 用户操作：用户请求发布，收到拒绝后查询正式版本和运行流程
- 预期结果：发布因重复标识被明确拒绝，不产生正式版本、运行流程或待办
- 场景结束：本场景没有创建任何运行资源

### S4 用户在深层并行等待时取消流程

- 参与用户：Flow 编辑用户、流程发起用户和被外派用户
- 开始状态：用户可以定义包含深层显式并行复核节点和后续安全批准的多阶段流程
- 用户操作：编辑用户定义并发布多阶段流程，发起用户启动；被外派用户查询到两个复核任务后，发起用户取消流程，被外派用户再尝试完成两个原任务，双方查询流程和后续阶段
- 预期结果：两个完成请求都被拒绝，不执行汇总、安全批准、发布或通知
- 场景结束：流程已取消，没有待处理外派任务

### S5 用户反转两个并行复核的完成顺序

- 参与用户：Flow 编辑用户、流程发起用户和两组被外派用户
- 开始状态：用户可以定义包含显式并行复核节点、汇总和安全批准的多阶段流程
- 用户操作：编辑用户定义并发布多阶段流程，发起用户启动两个实例；一个流程按后端到前端完成，另一个按前端到后端完成，每次完成后重新查询并继续安全批准
- 预期结果：完成顺序不改变层级、结果归属、汇总次数或最终业务结果
- 场景结束：两个流程都已完成且没有待处理任务

### S6 用户运行调整过复核层级的 Flow

- 参与用户：Flow 编辑用户、流程发起用户和被外派用户
- 开始状态：用户已有多阶段流程，并准备只把后端复核从第二层移动到准备阶段的直接下一层
- 用户操作：编辑用户修改层级并发布调整后的 Flow，发起用户启动；被外派用户查询并完成所有复核和安全批准，再查询完整历史
- 预期结果：后端复核显示新的直接所属层级，前端复核层级不变，流程仍按真实层级推进且不重复
- 场景结束：调整后的流程已完成，没有待处理外派任务

### S7 用户未添加并行节点时同级步骤保持串行

- 参与用户：Flow 编辑用户、流程发起用户和被外派用户
- 开始状态：用户定义一个普通自动步骤，其直接子步骤依次为外部确认及确认完成后的自动收尾，没有添加并行节点
- 用户操作：用户发布并启动流程，在外部确认等待期间查询步骤历史；被外派用户完成确认后，发起用户再次查询收尾步骤和最终结果
- 预期结果：等待期间只出现外部确认，后面的同级自动收尾不会提前执行；确认分支完整结束后才执行收尾
- 场景结束：流程按定义顺序完成，没有待处理任务

## 验证方式

### S1

1. 编辑用户定义并发布包含显式并行复核节点、汇总和安全批准的多阶段 Flow，发起用户启动。
2. 被外派用户查询后端复核和前端复核，完成一个后重新查询剩余任务。
3. 用户完成第二个复核，查询并确认只出现一次汇总，再查询和完成安全批准。
4. 用户查询完整历史，确认十二个业务步骤各执行一次、流程已完成且待办为空。

### S2

1. 编辑用户定义并发布包含显式并行复核节点、复核汇总后才产生安全批准的多阶段 Flow，发起用户启动并只保留运行流程编号。
2. 被外派用户第一次查询两个复核任务，完成一个后再次查询。
3. 用户完成剩余复核，再次查询此时才出现的安全批准并完成。
4. 用户查询并确认流程已完成且待办为空。

### S3

1. 用户准备只包含一个跨层重复步骤标识的 Flow。
2. 用户请求发布并观察明确拒绝。
3. 用户查询正式版本、运行流程和待办数量。
4. 用户确认没有创建任何正式或运行资源。

### S4

1. 编辑用户定义并发布包含深层显式并行复核节点的多阶段 Flow，发起用户启动，被外派用户查询到两个并行复核任务。
2. 发起用户取消流程，被外派用户尝试完成两个原任务。
3. 双方查询流程状态、汇总及所有后续阶段。
4. 用户确认流程已取消、完成请求被拒绝且待办为空。

### S5

1. 编辑用户定义并发布包含显式并行复核节点和后续安全批准的多阶段 Flow，发起用户启动两个独立实例并分别查询并行复核任务。
2. 两组用户按相反顺序完成复核，每次完成后都重新查询。
3. 两组用户分别查询和完成后续安全批准，再查询完整历史。
4. 用户确认两个流程都已完成，层级、结果归属和汇总次数一致。

### S6

1. 编辑用户修改后端复核层级并发布调整后的 Flow，发起用户启动。
2. 被外派用户查询两个复核任务，并查看它们各自的直接所属阶段。
3. 用户依次完成两个复核，重新查询并完成后续安全批准。
4. 用户查询并确认调整后的层级正确、流程已完成且没有重复或待办。

### S7

1. 用户定义并发布一个没有并行节点、普通父步骤下依次包含外部确认和自动收尾的流程，再启动实例。
2. 被外派用户查询到外部确认，发起用户查询历史并确认自动收尾尚未执行。
3. 被外派用户完成查询所得确认任务，发起用户重新查询步骤历史和流程结果。
4. 用户确认确认分支结束后才执行自动收尾，流程已完成且没有待办。
