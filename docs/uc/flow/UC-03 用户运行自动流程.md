# UC-03 用户运行自动流程

## 验证标识

- UC：`UC-03`
- 状态：`ACCEPTED`
- 领域：`flow`
- 需求基线：`用户确认的 Flow 完整用户路径规则@2026-07-28`
- 依赖：`UC-01`、`UC-02`

## 验证目标

验证用户启动只包含自动步骤的 Flow 后，系统按定义顺序执行并返回最终结果；明确
失败、意外异常、系统重启和终态重复操作不会造成跳步、重复、部分运行或遗留流程。

## 验证场景

### S1 用户完成包含三个自动步骤的流程

- 参与用户：流程发起用户
- 开始状态：一个包含第一步、第二步和第三步的 Flow 已经发布
- 用户操作：用户启动流程并查询运行结果及完整步骤历史
- 预期结果：三个步骤按照定义顺序各执行一次并完成
- 场景结束：流程已完成，没有活动步骤

### S2 同一 Flow 的两个运行流程独立完成

- 参与用户：两个流程发起用户
- 开始状态：同一个三步骤 Flow 已经发布
- 用户操作：用户连续启动两次，并分别查询两个运行流程和步骤历史
- 预期结果：两个运行流程拥有各自独立的编号和完整历史，数据互不共享
- 场景结束：两个流程都已完成

### S3 第二个自动步骤明确失败

- 参与用户：流程发起用户
- 开始状态：第二个步骤会返回明确失败结果
- 用户操作：用户启动流程并查询最终状态、已执行步骤和未执行步骤
- 预期结果：第一步完成、第二步失败、第三步不执行，流程明确显示失败
- 场景结束：流程已失败，没有活动步骤

### S4 第二个自动步骤发生意外异常

- 参与用户：流程发起用户
- 开始状态：第二个步骤会发生未处理异常
- 用户操作：用户记录启动前运行数量，启动流程，收到异常后重新查询
- 预期结果：异常明确返回给用户，本次启动没有留下部分流程或中间步骤历史
- 场景结束：本次运行流程未创建

### S5 系统重启后用户启动已发布 Flow

- 参与用户：流程发起用户
- 开始状态：三步骤 Flow 已发布，随后系统完成一次重启
- 用户操作：用户在重启后查询该 Flow，启动并查询完整运行结果
- 预期结果：三个步骤仍按原顺序各执行一次，没有跳过、重复或顺序变化
- 场景结束：流程已完成

### S6 用户取消已经完成的流程

- 参与用户：流程发起用户
- 开始状态：流程已经完成且完整历史可查询
- 用户操作：用户再次请求取消，然后重新查询流程和步骤历史
- 预期结果：取消被明确拒绝，完成状态、历史数量、顺序和内容均保持不变
- 场景结束：流程仍保持已完成

## 验证方式

### S1

1. 用户发布三步骤 Flow 并启动。
2. 用户查询运行流程和完整步骤历史。
3. 用户比较三个步骤的执行顺序、次数和结果。
4. 用户确认流程已完成且没有活动步骤。

### S2

1. 用户对同一个 Flow 发起两次独立启动。
2. 用户分别按返回编号查询两个运行流程。
3. 用户比较两个流程的编号、步骤编号、顺序和数量。
4. 用户确认两个流程都有独立完整历史并已完成。

### S3

1. 用户发布第二步会明确失败的 Flow。
2. 用户启动并查询流程结果。
3. 用户查询步骤历史，确认第一步完成、第二步失败且第三步不存在。
4. 用户确认流程已失败且没有活动步骤。

### S4

1. 用户记录启动前能够查询到的运行流程数量。
2. 用户启动会发生意外异常的 Flow。
3. 用户收到异常后重新查询运行流程和步骤历史。
4. 用户确认本次启动没有留下任何部分运行记录。

### S5

1. 用户发布 Flow，等待系统完成重启。
2. 用户重新查询该 Flow 并启动。
3. 用户查询三个步骤的顺序、次数和结果。
4. 用户确认流程已完成且没有跳步或重复。

### S6

1. 用户先完成一个三步骤流程并查询完整历史。
2. 用户对该流程再次发起取消。
3. 用户观察明确拒绝并重新查询状态和历史。
4. 用户确认流程仍已完成且所有历史不变。
