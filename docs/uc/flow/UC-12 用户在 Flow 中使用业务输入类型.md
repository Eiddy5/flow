# UC-12 用户在 Flow 中使用业务输入类型

## 验证标识

- UC：`UC-12`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`流程编排`
- 需求基线：`用户确认的外部业务 Input 扩展及输入规则归属@2026-09-09`
- 依赖：`UC-01、UC-02、UC-04`

## 验证目标

用户可以在 Flow 的启动输入、步骤输入和 Pause 恢复输入中使用业务系统提供的输入
类型，并完成发布、重新查询和运行。业务输入自己的定义规则、值转换和校验规则始终
生效，重新打开已保存的流程后仍保留这些规则。无效输入定义不能发布为可运行流程，
非法运行输入不能被当作有效业务数据继续处理。

## 验证场景

### S1 用户发布并运行包含业务输入的 Flow

- 参与用户：业务系统的 Flow 定义用户、发起用户和处理用户
- 开始状态：业务系统提供一种内置输入类型之外的业务输入，并明确它的合法定义、合法值以及值转换前后的样本；用户尚未创建本场景的 Flow
- 用户操作：定义用户在启动输入、一个处理步骤的输入和一个 Pause 的恢复输入中使用该业务类型，配置合法默认值，并同时保留一个内置输入；用户保存、发布后离开当前编辑内容，再按 Flow key 和版本查询正式定义；发起用户提交业务输入并启动，处理用户查询当前 Pause 并提交业务结果，最后重新查询运行结果
- 预期结果：正式定义保留各位置的业务输入类型、配置与默认值；流程能够运行，业务输入按已声明规则转换，后续步骤可以使用转换后的启动值和 Pause 结果；内置输入仍按原定义生效
- 场景结束：Flow 已完成，没有活动步骤或等待恢复的 Pause

### S2 用户发布包含非法业务输入的定义

- 参与用户：业务系统的 Flow 定义用户
- 开始状态：业务系统已明确业务输入的合法配置与不合法配置，用户分别准备在启动输入、步骤输入和 Pause 恢复输入中使用不合法配置的独立草稿；不合法配置包含违反该业务类型规则的默认值
- 用户操作：用户分别保存并查询草稿，尝试发布，每次失败后重新查询草稿和正式版本，最后删除这些草稿
- 预期结果：每份非法定义的发布都被明确拒绝，不返回可使用的正式定义，也不产生可运行版本；已保存草稿原文保留，不能把非法业务输入静默改为内置类型或忽略其规则后发布
- 场景结束：本场景草稿均已删除，没有产生可运行版本或运行实例

### S3 非法启动值被拒绝后用户提交合法业务值

- 参与用户：业务系统的 Flow 发起用户
- 开始状态：用户已独立发布一个包含必填业务启动输入和结果观察步骤的简单 Flow；该业务类型有明确的非法值、合法值和转换结果
- 用户操作：用户先提交违反业务规则的输入请求启动，随后查询本场景运行记录；再提交合法值启动，按取得的运行编号查询最终结果
- 预期结果：非法值不能启动 Flow，也不能产生步骤结果；合法值可启动独立实例，后续步骤取得业务类型转换后的正确值
- 场景结束：非法提交没有创建运行实例；合法提交的 Flow 已完成，没有活动步骤

### S4 非法恢复值被拒绝后用户纠正业务结果

- 参与用户：业务系统的 Flow 发起用户和处理用户
- 开始状态：用户可独立定义包含一个 Pause 的 Flow，该 Pause 使用业务恢复输入，后续步骤读取其结果；该业务类型有明确的非法值、合法值和转换结果
- 用户操作：用户定义、发布并启动 Flow，处理用户查询运行信息并识别正在等待的具体 Pause；向查询所得 Pause 提交非法业务值，重新查询状态，再提交合法值并查询最终结果
- 预期结果：非法提交被明确拒绝，原 Pause 保持等待，没有接纳非法结果或执行后续步骤；合法提交后同一实例继续，后续步骤使用业务类型转换后的正确结果
- 场景结束：Flow 已完成，没有等待恢复的 Pause

### S5 重新进入系统后用户继续使用已保存的业务输入

- 参与用户：业务系统的 Flow 定义用户、发起用户和处理用户
- 开始状态：业务输入类型及其规则在本次操作期间保持不变，用户尚未创建本场景的 Flow
- 用户操作：用户独立定义并发布包含业务启动输入、步骤输入和业务 Pause 恢复输入的 Flow，启动后查询到 Pause；系统完成重启后，用户按 Flow key 和版本重新查询正式定义，再按运行编号查询同一实例及当前 Pause；处理用户先提交非法值，重新查询后提交合法值，再查询最终结果
- 预期结果：重新查询后业务输入类型、配置和默认值保持不变；先前已接纳的启动值仍可查询；业务恢复规则仍拒绝非法值且不提前推进；合法提交使同一实例继续，后续步骤取得正确业务结果
- 场景结束：同一 Flow 运行实例已完成，没有活动步骤或等待恢复的 Pause

## 验证方式

### S1

1. 用户准备业务系统提供的输入类型、合法配置、合法默认值、待转换的输入及预期转换结果，并定义包含观察步骤和一个 Pause 的 Flow。
2. 用户从公开 Flow 管理能力保存并发布，离开编辑内容后按 key 和版本重新查询正式定义，核对三处业务输入和内置输入。
3. 用户启动 Flow，查询并识别当前 Pause，提交业务结果，再重新查询后续步骤结果。
4. 用户核对转换后的启动值、Pause 结果和内置输入结果，确认 Flow 已完成且没有活动步骤。

### S2

1. 用户分别准备在三种输入位置使用非法配置的独立草稿，包含不符合业务输入规则的默认值。
2. 用户从公开 Flow 管理能力保存、查询并尝试发布每份草稿，观察明确拒绝。
3. 用户重新查询草稿原文和正式版本，确认原文保留且没有可运行版本。
4. 用户删除全部场景草稿并查询确认清理完成，没有运行实例。

### S3

1. 用户独立发布带业务启动输入的简单 Flow，准备业务规则明确拒绝的值和可转换为确定结果的合法值。
2. 用户从公开 Flow 启动能力提交非法值，随后查询确认没有新运行实例或步骤结果。
3. 用户提交合法值启动，按运行编号重新查询输入、后续步骤结果与状态。
4. 用户核对转换结果，确认合法实例已完成且没有活动步骤。

### S4

1. 用户独立定义、发布并启动带业务恢复输入的 Flow，从公开运行查询中识别当前 Pause。
2. 用户向查询所得 Pause 提交非法值，观察明确拒绝，再查询确认仍在等待且后续步骤尚未执行。
3. 用户向同一 Pause 提交合法值，重新查询 Pause 结果与后续步骤结果，核对业务转换结果。
4. 用户查询确认同一实例已完成且没有等待恢复的 Pause。

### S5

1. 用户独立发布在三种输入位置使用业务类型的 Flow，启动并查询到 Pause，记录公开查询获得的 Flow key、版本和运行编号。
2. 系统完成重启后，用户重新进入系统，使用这些标识查询正式定义、已接纳输入和当前 Pause，核对业务配置与默认值。
3. 用户向重新查询所得 Pause 提交非法值，重新查询确认没有推进；随后提交合法值，再查询业务结果与后续步骤结果。
4. 用户确认业务规则仍然生效、同一实例已完成且没有活动步骤或等待恢复的 Pause。
