# UC-04 用户恢复处于 Pause 的 Flow

## 验证标识

- UC：`UC-04`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`任务类型`
- 目标任务类型：`PAUSE`
- 需求基线：`用户确认的 Flow Pause 用户操作路径@2026-08-27`
- 依赖：`UC-02`、`UC-03`

## 验证目标

验证 Flow 运行到 Pause 后，用户能够通过 Flow 查询识别准确的运行实例和 Pause
步骤，提交 Pause 结果并使该 Flow 继续运行；非法输入、重复恢复、跨租户、实例选择、
取消、恢复后的处理异常和系统重启不会造成越权、重复推进、部分完成或状态混用。

## 验证场景

### S1 用户查询并恢复单个处于 Pause 的 Flow

- 参与用户：Flow 发起用户和 Flow 处理用户
- 开始状态：用户可以定义并发布包含唯一目标 Pause 的标准验证 Flow
- 验证流程：开始后由前置步骤准备输入，进入唯一目标 Pause 任务，恢复后由后置观察步骤读取目标任务结果并结束
- 用户操作：用户定义、发布并启动 Flow，查询运行状态和目标 Pause；处理用户向查询所得 Pause 提交结果，双方再查询最终结果
- 预期结果：Pause 状态可以从 Flow 中查询；结果提交后同一个 Flow 继续执行，后置步骤取得提交结果
- 场景结束：Flow 已完成，没有仍在等待恢复的 Pause 步骤

### S2 用户提交 Pause 结果后只推进当前 Flow

- 参与用户：Flow 发起用户和 Flow 处理用户
- 开始状态：用户可以定义 Pause 恢复后继续处理的标准验证 Flow
- 验证流程：开始后由前置步骤准备输入，进入唯一目标 Pause 任务，恢复后由后置观察步骤读取目标任务的批准结果并结束
- 用户操作：用户定义、发布并启动 Flow，查询唯一目标 Pause 并提交批准结果，再查询 Pause 结果、Flow 历史和后续步骤
- 预期结果：提交结果只用于当前 Flow 的目标 Pause，目标 Pause 和后续步骤各执行一次
- 场景结束：Flow 已完成，没有重复步骤或等待恢复的 Pause

### S3 非法输入后用户使用正确结果恢复 Flow

- 参与用户：Flow 处理用户和 Flow 发起用户
- 开始状态：用户可以定义并发布包含唯一目标 Pause 的标准验证 Flow
- 验证流程：开始后由前置步骤准备输入，进入唯一目标 Pause 任务，合法恢复后由后置观察步骤读取目标任务结果并结束
- 用户操作：用户定义、发布并启动 Flow，查询目标 Pause；依次提交不存在的运行编号、空白 Pause 标识和缺失结果，再重新查询并提交合法结果
- 预期结果：每个非法请求都被明确拒绝，拒绝期间 Flow 和 Pause 状态不变；合法结果能够恢复 Flow
- 场景结束：Flow 已完成，没有遗留等待恢复的 Pause

### S4 用户重复恢复已经结束的 Pause

- 参与用户：Flow 处理用户
- 开始状态：用户可以定义并发布包含唯一目标 Pause 的标准验证 Flow
- 验证流程：开始后由前置步骤准备输入，进入唯一目标 Pause 任务，恢复后由后置观察步骤读取目标任务结果并结束
- 用户操作：用户定义、发布并启动 Flow，查询并恢复目标 Pause 使 Flow 结束，再次向同一 Pause 提交结果，然后重新查询 Flow 和步骤历史
- 预期结果：重复提交被明确拒绝，已完成结果、Flow 历史和步骤数量不变
- 场景结束：Flow 仍保持已完成

### S5 其他租户查询或恢复处于 Pause 的 Flow

- 参与用户：租户 A 的 Flow 用户和租户 B 用户
- 开始状态：租户 A 用户可以定义并发布包含唯一目标 Pause 的标准验证 Flow
- 验证流程：开始后由前置步骤准备输入，进入租户 A Flow 的唯一目标 Pause 任务，恢复后由后置观察步骤读取目标任务结果并结束
- 用户操作：租户 A 用户定义、发布并启动 Flow；租户 B 查询并尝试恢复该 Flow；租户 A 用户随后重新查询目标 Pause 并提交结果
- 预期结果：租户 B 看不到租户 A 的运行实例且恢复请求被拒绝，租户 A 的 Flow 不受影响
- 场景结束：租户 A 的 Flow 已完成

### S6 同一用户在两个处于 Pause 的 Flow 间选择准确实例

- 参与用户：同一 Flow 处理用户
- 开始状态：用户可以定义并发布包含唯一目标 Pause 的标准验证 Flow
- 验证流程：两个独立运行实例都在前置步骤后进入各自的唯一目标 Pause 任务，恢复后由各自后置观察步骤读取目标任务结果并结束
- 用户操作：用户定义并发布验证 Flow，启动两个独立实例，查询两个实例及其 Pause；先恢复第二个实例，再重新查询并恢复第一个实例
- 预期结果：每次提交只推动所选运行实例，不会把结果写入另一个 Flow 实例
- 场景结束：两个 Flow 运行实例都已完成

### S7 Flow 取消后用户恢复原 Pause

- 参与用户：Flow 发起用户和 Flow 处理用户
- 开始状态：用户可以定义并发布包含唯一目标 Pause 的标准验证 Flow
- 验证流程：开始后由前置步骤准备输入，进入唯一目标 Pause 任务，合法恢复后由后置观察步骤读取目标任务结果并结束
- 用户操作：用户定义、发布并启动 Flow，查询目标 Pause 后取消 Flow；再使用原查询结果提交恢复，并查询 Flow 和步骤历史
- 预期结果：恢复请求被明确拒绝，不会重新启动已取消的 Flow 或创建后续步骤
- 场景结束：Flow 保持已取消，没有等待恢复的 Pause

### S8 Pause 结果提交后的后续处理发生异常

- 参与用户：Flow 处理用户和 Flow 发起用户
- 开始状态：用户可以定义目标 Pause 恢复后会发生后续异常的标准验证 Flow
- 验证流程：开始后由前置步骤准备输入，进入唯一目标 Pause 任务，恢复后由后置观察步骤读取目标任务结果但发生意外异常
- 用户操作：用户定义、发布并启动 Flow，查询目标 Pause 并提交结果；收到异常后重新查询，再取消 Flow 完成本场景清理
- 预期结果：异常明确返回，Flow 和目标 Pause 恢复为提交前的等待状态，不产生部分后续结果
- 场景结束：Flow 已取消，没有等待恢复的 Pause

### S9 系统重启后用户继续恢复处于 Pause 的 Flow

- 参与用户：Flow 发起用户和 Flow 处理用户
- 开始状态：用户可以定义并发布包含唯一目标 Pause 的标准验证 Flow
- 验证流程：开始后由前置步骤准备输入，进入唯一目标 Pause 任务，恢复后由后置观察步骤读取目标任务结果并结束
- 用户操作：用户定义、发布并启动 Flow，确认目标 Pause 正在等待后完成系统重启；重启后重新查询同一 Flow 和 Pause，提交结果并查询最终状态
- 预期结果：无需依赖重启前保存的页面对象或内部信息，也能通过 Flow 查询找到同一 Pause 并继续同一运行实例
- 场景结束：Flow 已完成，没有等待恢复的 Pause

## 验证方式

### S1

1. 用户定义并发布标准验证 Flow，启动后查询到目标运行实例处于 Pause。
2. 用户从 Flow 的步骤信息中识别目标 Pause，并提交合法结果。
3. 用户重新查询 Flow 和步骤历史，确认后置步骤取得 Pause 结果。
4. 用户确认 Flow 已完成且没有等待恢复的 Pause。

### S2

1. 用户定义并发布标准验证 Flow，启动后查询唯一目标 Pause。
2. 用户向查询所得 Pause 提交批准结果。
3. 用户重新查询 Pause 结果、原等待步骤和后续步骤的执行次数。
4. 用户确认每个步骤只执行一次且 Flow 已完成。

### S3

1. 用户定义并发布标准验证 Flow，启动后查询目标 Pause。
2. 用户依次提交三类非法输入，每次拒绝后都重新查询 Flow 和 Pause 状态。
3. 用户使用查询所得运行实例和 Pause 提交合法结果。
4. 用户确认 Flow 已完成且没有等待恢复的 Pause。

### S4

1. 用户定义并发布标准验证 Flow，启动后查询并恢复目标 Pause，使 Flow 结束。
2. 用户再次向同一 Pause 提交结果。
3. 用户观察明确拒绝并重新查询 Flow 和步骤历史。
4. 用户确认 Flow 仍已完成且所有结果和数量不变。

### S5

1. 租户 A 用户定义并发布标准验证 Flow，启动后查询到目标 Pause。
2. 租户 B 用户查询并尝试恢复该 Flow。
3. 租户 A 用户重新查询，确认 Flow 和 Pause 没有变化，再提交结果。
4. 租户 A 用户查询并确认 Flow 已完成。

### S6

1. 用户定义并发布标准验证 Flow，启动两个独立实例并查询到各自的 Pause。
2. 用户根据运行编号先恢复第二个实例。
3. 用户重新查询，确认第一个仍处于 Pause 且第二个已完成，再恢复第一个。
4. 用户确认两个 Flow 运行实例都已完成。

### S7

1. 用户定义并发布标准验证 Flow，启动后查询并记录目标 Pause。
2. 用户取消 Flow。
3. 用户向原 Pause 提交结果并观察拒绝。
4. 用户查询并确认 Flow 已取消且没有等待恢复的 Pause。

### S8

1. 用户定义并发布后置观察会发生异常的标准验证 Flow，启动后查询目标 Pause 并尝试恢复。
2. 用户收到后续处理异常。
3. 用户重新查询，确认 Flow 仍处于原 Pause 且没有部分推进。
4. 用户取消 Flow 并确认没有等待恢复的 Pause。

### S9

1. 用户定义并发布标准验证 Flow，启动后查询确认目标 Pause 正在等待。
2. 系统完成重启，用户重新登录并查询同一 Flow。
3. 用户从 Flow 步骤信息中重新识别 Pause，提交结果并查询完整历史。
4. 用户确认同一 Flow 已完成且没有等待恢复的 Pause。
