# UC-13 用户调用并追溯子流程

## 验证标识

- UC：`UC-13`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`任务类型`
- 目标任务类型：`SubFlow`
- 需求基线：`用户确认的统一 inputs、独立子运行与来源追溯及首次调用闭环@2026-09-10`
- 依赖：`UC-01`、`UC-02`、`UC-04`

## 验证目标

用户能够以统一的步骤输入调用子流程，查询独立子运行及其直接来源和最初来源；
子流程暂停期间父调用持续等待，用户恢复子流程后，返回结果被父后续步骤消费并完成。
非法输入、无法启动和子流程运行失败均明确结束本次调用，不让父流程永久等待或错误执行后续步骤。

## 验证场景

### S1 子流程暂停后恢复并向父流程返回结果

- 参与用户：流程编排用户、流程发起用户和 Pause 处理用户
- 开始状态：用户可以定义并发布父子流程，本场景尚未启动运行实例
- 验证流程：父流程先准备一个确定输入，经唯一目标 SubFlow 任务 调用子流程，再由后置观察步骤消费返回结果并结束；子流程接收输入、进入一个 Pause，恢复后产生包含输入和处理结果的返回值并结束
- 用户操作：编排用户使用与其他步骤一致的 inputs 配置子调用并发布父子流程；发起用户启动父流程，查询父调用和不同编号的子运行及其输入、来源；处理用户查询子运行中正在等待的具体 Pause，提交结果恢复，再重新查询后续步骤和父子运行结果
- 预期结果：不需要额外的 arguments 配置，子流程接收到父调用绑定的正确输入；子运行独立可查询，直接来源和最初来源均指向本次父运行；子流程暂停期间父调用保持运行且父后置步骤尚未执行；恢复子流程后子运行完成，父调用返回正确结果，父后置步骤消费该结果，无需再恢复父调用
- 场景结束：父子运行均已完成，没有活动步骤或等待恢复的 Pause，来源与结果仍可查询

### S2 嵌套子调用保留直接来源与最初来源

- 参与用户：流程编排用户和流程发起用户
- 开始状态：用户可以定义并发布三层流程，本场景尚未启动运行实例
- 验证流程：顶层流程准备输入、调用中层流程、消费返回结果并结束；中层流程接收输入、调用底层流程、消费返回结果并结束；底层流程接收输入并产生确定结果后结束；两个 SubFlow 任务分属顶层和中层，用于验证跨层来源及结果返回
- 用户操作：编排用户用统一步骤输入发布三层流程；发起用户启动顶层流程，查询顶层、中层及底层运行，沿来源关系重新查询各层输入、结果和结束状态
- 预期结果：三层运行编号各不相同；中层的直接来源和最初来源均为顶层，底层的直接来源为中层、最初来源为顶层；各层输入按配置传递，底层结果被中层消费，中层返回结果被顶层消费；结束后仍可沿来源查询各自运行历史
- 场景结束：三层运行均已完成，没有活动步骤或等待恢复的 Pause

### S3 子流程启动输入不合法

- 参与用户：流程编排用户和流程发起用户
- 开始状态：用户可以独立定义父子流程，子流程声明必填且有明确类型的输入
- 验证流程：父流程准备不满足子流程必填或类型要求的值，经唯一目标 SubFlow 任务 发起调用，成功时才由后置观察步骤消费结果并结束；子流程仅在合法输入下产生确定结果并结束
- 用户操作：编排用户分别为缺少必填值和类型不合法准备独立父子流程并发布，通过统一步骤 inputs 配置传参；发起用户分别启动父流程，重新查询父调用结果、子运行记录与父后置步骤
- 预期结果：每次非法输入都被明确拒绝，父调用和父运行均显示失败；子流程没有接纳非法值开始业务步骤，也没有产生成功结果；父后置步骤不执行
- 场景结束：本场景父运行均已失败，没有活动子运行或等待恢复的 Pause

### S4 调用时目标子流程不可运行

- 参与用户：流程编排用户和流程发起用户
- 开始状态：用户可以独立发布父子流程，并在启动父流程前使所引用的子流程定义不可再用于启动
- 验证流程：父流程准备合法输入，经唯一目标 SubFlow 任务 调用目标子流程，成功时才由后置观察步骤消费结果并结束；子流程原本可接收输入并产生确定结果
- 用户操作：编排用户定义并发布父子流程，再通过流程管理删除本次被引用的子流程定义，重新查询确认目标不可运行；发起用户启动父流程并查询父调用结果、子运行记录和父后置步骤
- 预期结果：子调用明确报告目标不可运行，父调用和父运行均显示失败；没有启动目标子运行，没有产生子流程成功结果，父后置步骤不执行
- 场景结束：父运行已失败，没有活动子运行或等待恢复的 Pause

### S5 子流程运行失败后父调用失败

- 参与用户：流程编排用户和流程发起用户
- 开始状态：用户可以独立定义父子流程，子流程的业务处理在给定合法输入下会明确失败
- 验证流程：父流程准备合法输入，经唯一目标 SubFlow 任务 调用子流程，成功时才由后置观察步骤消费结果并结束；子流程接收输入后执行会明确失败的业务处理
- 用户操作：编排用户定义并发布父子流程；发起用户启动父流程，查询独立子运行及业务失败结果，再重新查询父调用、父后置步骤和父子终态
- 预期结果：子运行显示失败并保留失败记录及来源关系；父调用和父运行随之失败，不返回伪造的成功结果，父后置步骤不执行
- 场景结束：父子运行均已失败，没有活动步骤或等待恢复的 Pause

## 验证方式

### S1

1. 编排用户通过公开流程管理能力定义并发布本场景父子流程，在 SubFlow 的统一 inputs 中配置确定输入，在子流程中配置一个 Pause 和确定返回结果。
2. 发起用户通过公开启动能力启动父流程，通过运行查询取得子运行编号，核对输入、独立运行记录、直接来源与最初来源。
3. 处理用户查询子运行中当前具体 Pause，确认父调用尚在运行且父后置步骤未执行，再向查询所得 Pause 提交结果。
4. 用户重新查询子后续步骤及返回结果，再查询父调用与后置消费结果，核对输入和处理结果均正确传回。
5. 用户查询确认父子运行均完成，无需恢复父调用，没有活动步骤或等待恢复的 Pause，来源与结果可重新查询。

### S2

1. 编排用户通过公开流程管理能力独立定义并发布三层流程，每层使用可区分的输入和返回结果。
2. 发起用户启动顶层流程，通过公开运行查询找到中层及底层运行，记录用户可见的三个运行编号。
3. 用户重新查询来源，核对中层直接来源和最初来源均为顶层，底层直接来源为中层且最初来源为顶层。
4. 用户查询各层输入、返回值和后置消费结果，确认结果逐层返回且没有混用层级。
5. 用户查询确认三层运行均完成，没有活动步骤或等待恢复的 Pause，再沿来源关系查询各层历史。

### S3

1. 编排用户分别定义并发布缺少子必填值和传递非法类型值的独立验证流程，确保父流程可合法启动，非法值发生于子调用传参。
2. 发起用户通过公开能力分别启动父流程，再查询对应子调用的输入拒绝结果与父运行状态。
3. 用户查询子运行和步骤记录，确认非法值未被接纳用于子业务处理、没有成功结果且父后置步骤未执行。
4. 用户查询确认父运行均失败，没有活动子运行或等待恢复的 Pause。

### S4

1. 编排用户独立定义并发布父子流程，再通过公开流程管理能力删除被引用的子定义，查询确认目标已不可启动。
2. 发起用户启动父流程并通过公开运行查询观察子调用的目标不可运行错误。
3. 用户查询确认没有启动子运行、没有子成功结果且父后置步骤未执行。
4. 用户确认父运行已失败，没有活动子运行或等待恢复的 Pause。

### S5

1. 编排用户独立定义并发布子业务处理会失败的父子流程，准备能够合法启动子流程的确定输入。
2. 发起用户启动父流程，通过公开运行查询找到本次子运行，核对输入、来源和业务失败记录。
3. 用户查询父调用及父后置步骤，确认失败传回父调用，没有成功返回结果且后置步骤未执行。
4. 用户重新查询确认父子运行均失败，没有活动步骤或等待恢复的 Pause，子失败历史与来源仍可查询。
