# UC-15 用户通过上游 Flow 完成启动流程

## 验证标识

- UC：`UC-15`
- 状态：`ACCEPTED`
- 领域：`flow`
- UC 类型：`流程运行`
- 需求基线：`用户确认的单个上游 Flow 达到指定终态后触发另一 Flow@2026-09-17`
- 依赖：`UC-01、UC-02`

## 验证目标

用户在目标 Flow 中配置一个上游流程及其成功完成条件，启动上游后即可自动启动目标
Flow，并能查询两个流程各自的运行结果直至完成。

## 验证场景

### S1 上游成功完成后自动启动目标 Flow

- 参与用户：同一租户的 Flow 管理用户和发起用户
- 开始状态：用户已有两个各自只有单一正式版本且能自动完成的简单 Flow；目标 Flow 仅配置一个以指定上游 Flow 成功完成为条件的触发器，两个流程没有循环触发关系；本次尚未启动上游，系统持续可用且没有其他启动操作
- 用户操作：用户查询目标 Flow 的触发配置和两个流程的现有运行记录；通过公开启动能力启动一次上游 Flow，查询上游结果，再查询目标 Flow 新增的运行实例并跟进最终结果
- 预期结果：上游成功完成后，目标 Flow 自动新增一个不同编号的运行实例，不需要用户再手动启动目标；目标按自身定义完整执行，上游保持成功完成
- 场景结束：本次上游与目标运行实例均已完成，没有活动步骤或等待处理的任务

## 验证方式

### S1

1. 用户通过公开 Flow 查询选择本场景上游和目标，确认目标定义中的上游名称与成功完成条件，并记录两个流程的已有运行实例。
2. 发起用户通过公开启动能力只启动一次上游，按返回的运行编号查询并确认上游成功完成。
3. 用户通过目标 Flow 的运行查询识别本次新增实例，确认只新增一个且编号不同于上游实例，并查询其步骤历史和结果。
4. 用户重新查询上游与目标实例，确认二者均已完成，没有活动步骤或等待处理的任务。
