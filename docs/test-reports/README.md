# UC 测试报告

本目录保存 Test Agent 根据 `docs/uc/` 中的 UC Markdown 文档执行测试后
生成的近期报告。

## 目录结构

测试报告按照 UC 领域归档：

```text
docs/test-reports/
  flow/
    UC-01-2026-07-27-1530.md
    BATCH-2026-07-27-1700.md
  external-task/
    UC-04-2026-07-27-1600.md
```

领域目录必须与目标 UC 的 UC 领域归属一致。不能使用 `misc`、`other` 或
`common` 等模糊目录。

## 文件命名

报告文件名使用：

```text
<UC-ID>-<YYYY-MM-DD-HHmm>.md
```

同一个 UC 每次执行都生成名称唯一且内容自包含的新报告。复验报告必须带入仍未解决
的反例和本次复验证据，不能依赖更早报告才能理解。

批量验证两个或更多 UC 时，同时生成：

```text
BATCH-<YYYY-MM-DD-HHmm>.md
```

批量报告放在对应 UC 领域目录，只汇总本次执行，不替代每个 UC 的独立报告。批次
跨多个领域时，每个领域分别生成一份批量报告，最终交付再汇总全部领域。

## 报告保留

报告采用滚动保留，不作为永久档案。Test Agent 在生成报告后按照
[`uc-testing.md`](../standards/uc-testing.md#滚动保留) 清理超出上限的同类文件。
该规范是报告数量、排序、清理范围和长期事实归属的唯一来源。

## 内容要求

每份报告至少包含：

- UC 文档和唯一测试类路径。
- 测试时间、类型、环境和代码版本。
- 全部场景的测试方法映射。
- 每个场景的预期结果、结束状态、结论和执行证据。
- 执行命令与结果。
- PASS、FAIL、NOT_COVERED、BLOCKED 数量。
- 最终仍在运行的流程和仍在等待的任务数量。
- 失败、反例、构建产物和未解决事项。

批量报告至少汇总每个 UC 的文档、主测试类、场景数量、四种结论数量、独立报告
路径、执行命令、活动资源数量和未解决事项。

报告是测试执行事实，不是开发规范或 UC 定义。不得在报告中修改业务预期，也不得
记录密码、令牌、完整环境变量或其他秘密。
