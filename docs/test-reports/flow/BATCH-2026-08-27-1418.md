## 稳定反例

### CE-01：ActorRef 无法序列化，Flow 持久化入口整体失败

- 输入：各 UC 主测试内定义的租户/用户身份、YAML Flow 草稿及发布或保存命令。
- 预期：草稿可持久化，随后按各 UC 继续发布、启动、执行或验证非法定义。
- 触发：创建或发布 Flow 时进入 PostgreSQL 保存链路。
- 实际：Jackson 抛出 `InvalidDefinitionException: No serializer found for class org.cses.flow.core.domains.ActorRef and no properties discovered to create BeanSerializer`。
- 影响：UC 主测试 28 个已映射场景失败；Core 全量回归中 79 个失败具有同一异常签名。
- 复验：UC-01 S1 单方法复跑仍失败。
- 结论：这是稳定实现问题，不是环境阻塞。

### CE-02：Flow 状态不可变性架构约束失效

- 触发：`CoreArchitectureStandardTest.workflowRuntimeStateIsOwnedByTheFlowDomain`。
- 实际：断言要求 `State` 持有 `private final Type current` 和 `private final List<History> history`，当前源码不满足；错误为 `expected: <true> but was: <false>`。
- 复验：单方法复跑仍失败。
- 结论：这是独立于数据库和 CE-01 的稳定架构回归。
