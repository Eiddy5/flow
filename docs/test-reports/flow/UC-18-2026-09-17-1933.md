## 失败与反例

- CE-18-01（已修复）：首次真实运行持久化回读报 `Invalid TaskRun attempt`。可空 error 使用 JsonObject.getString 被读取为字面量 `"null"`，使 RUNNING Attempt 无法恢复。S1 单独复现后由主 Agent 修复 Codec 可空读取；同一S1、全部UC及nullableAttemptFieldsRoundTrip复验通过。
- CE-18-02（已修复）：重试时 `RunContext variable path is missing: taskRun.outputs`，首次快照内空对象经通用 NON_EMPTY 序列化裁掉，无法发起第二次真实调用。主 Agent 最终增加专用 encodeVariables 完整保留快照{}、[]、null；普通任务值继续原序列化协议。原场景及文本往返技术测试复验结果见下。
- CE-18-03（已修复）：原 ExecutorServiceTest 的 warning 路径期望实际 Worker 变量 taskRun.state=RUNNING，实际CREATED。主 Agent 调整首次快照在startTaskRun之后建立；原断言保持并复验。
- 中间修复曾扩大普通任务值的序列化范围，嵌套集成三例期望{}、实际含prepare-release空输出。最终收窄为仅retryVariables使用encodeVariables，普通输入输出encode恢复原逻辑；对应三例保持原断言复验。
