## 验证范围

全部场景通过公开 Service 运行，没有直接调用 Repository 或以数据库查询代替行为断言。
测试明确使用以下独立字面量作为版本预期：首次草稿 v1、首次发布 v2、修改草稿 v3、
再次发布 v4。发布前后的 Execution 分别断言永久绑定 v2 和 v4，系统重启后仍保持。

正式 Flow 删除同样是追加保存：单次草稿 v1 和发布 v2 后，删除返回不同数据库行
`id` 的 v3；通过 `FlowService.flow(..., 3)` 精确查询删除版本，并确认历史发布 v2
本身没有被改写为删除。

## 场景验证

| 场景 | 主测试方法 | 状态 | 预期结果与结束状态证据 |
| --- | --- | --- | --- |
| S1 用户启动并完成当前版本 | `s1UserStartsCurrentVersionAndCompletesItThroughPause` | PASS | 首次发布结果为 v2，Execution 创建、查询、重启恢复和完成均绑定 v2；Pause 输出正确，最终 SUCCESS、活动与等待步骤均为 0。 |
| S2 新版本发布前后的 Flow 分别完整运行 | `s2OldAndNewVersionsRunIndependently` | PASS | 首轮发布 v2，修改草稿 v3，再发布 v4；旧、新实例分别绑定 v2/v4，Pause 输出、Execution ID 与 TaskRun 历史互不混用，最终均 SUCCESS。 |
| S3 用户取消准确的目标 Flow | `s3CancelTargetsOnlyTheSelectedExecution` | PASS | 目标实例及其 Pause 进入 KILLED；同一 v2 的对照实例未受影响，可恢复至 SUCCESS，等待步骤清零。 |
| S4 用户启动不可用或不可见的 Flow | `s4UnavailableOrInvisibleFlowsAreRejectedWithoutRuns` | PASS | 未发布、删除、缺失及跨租户 Flow 均被拒绝；正式 Flow 的发布 v2 与删除 v3 为不同记录，v2 保持未删除、v3 精确查询为删除；没有 Execution 或 Pause 遗留。 |
| S5 用户取消不存在、越权或已经结束的 Flow | `s5InvalidCancellationKeepsTerminalAndControlExecutionsUnchanged` | PASS | 不存在、跨租户、SUCCESS 和已 KILLED 实例的错误取消均明确拒绝，终态和合法对照实例不被越权改变。 |
| S6 Flow 处于 Pause 期间发布新版本 | `s6PausedOldVersionDoesNotSwitchAfterNewVersionIsPublished` | PASS | 旧实例保持绑定 v2；草稿 v3、发布 v4 后启动的新实例绑定 v4；两条路径按各自 Task 数完成并清空等待步骤。 |
| S7 恢复 Pause 与取消 Flow 发生竞争 | `s7ResumeAndCancelRaceProducesOneConsistentTerminalResult` | PASS | 并发恢复与取消至少一方受理，最终只能是 SUCCESS 或 KILLED；Pause 与 Execution 终态一致，没有 PAUSED/CREATED/RUNNING 活动步骤。 |
| S8 同一 Flow 的两个运行实例独立完成 | `s8TwoExecutionsOfOneFlowKeepIndependentCompleteHistories` | PASS | 两个实例均绑定当前发布 v2，Execution ID 和 TaskRun ID 集合互不相交，各自完整执行三个步骤并 SUCCESS。 |
| S9 系统重启后用户启动已发布 Flow | `s9FreshServerStartsPersistedPublishedFlowInOrder` | PASS | 重启后查询到相同发布行 `id` 和 v2，所启动 Execution 绑定 v2；三个 Task 按定义顺序各运行一次并 SUCCESS。 |

补充集成类的 7 个测试分别加强 S1～S7 的重启恢复、精确版本查询、删除追加版本、
Execution 版本绑定及竞争终态证据；它们不额外增加 UC 场景计数。
