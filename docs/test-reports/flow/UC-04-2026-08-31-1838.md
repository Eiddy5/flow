## 测试范围

本轮针对已确认 UC-04 同步并执行全部 11 个场景。S10/S11 的退回写操作均通过公开
`ExecutionService.rewind(...)` 发起，并直接断言其 `RewindResult`，没有绕过 Service

## S10/S11 关键证据

- `RewindResult.affectedTaskRunIds()` 使用运行时产生的具体 TaskRun ID 做精确列表相等
  断言，不以数量或集合替代顺序验证。
- S10 列表只覆盖请求当时有效路径中 target→source 两端及真实 descendants；
  Sequence 父子均出现，Pause 的真实 child 出现，SKIPPED Route 作为叶子出现，未创建
  Route child 不存在于 Execution 且不在返回列表。
- S10 顺序是历史逆序/业务回滚顺序：较晚步骤与 child 在前，对应父步骤在后，target
  最后；片段前步骤和源之后未创建步骤均不在列表。
- S11 分别构造两组预期实际 ID；第二组逐项断言不属于第一组，因此不会把已成为历史的
  v1 TaskRun 混入 v2 返回。
- 两次退回的 Service 返回 Execution 均在等待异步结果之前断言：状态、状态历史、
  Generation current/history 和已有 TaskRun ID 顺序与请求提交时公开查询快照一致。
- `ExecutionControllerTest` 确认 rewind endpoint 的 Java 公开返回类型为 `RewindView`，
  覆盖 HTTP 返回协议变化。

## 失败与反例

### CE-01 Pause 恢复后的后置异常没有回滚到原等待点

- 场景：UC-04 S8。
- 用户输入：在唯一 Pause 上通过 `ExecutionService.resume(...)` 提交
  `{"decision":"APPROVED"}`；后续公开 RunnableTask 抛出
  `uc04-downstream-failure`。
- 预期：异常明确返回，Execution 和原 Pause 回到提交前 PAUSED，且不产生部分后续结果。
- 实际：异步处理后 `ExecutionService.execution(...)` 查询到 Execution=`FAILED`；
  测试在首个状态断言得到 `expected PAUSED but was FAILED`。
- 稳定性：整类执行失败一次，随后同一方法单独复验再次失败；模块和根级回归仍失败。
- 影响：UC-04 不能整体验收通过；S10/S11 的影响范围返回路径均独立通过。
- 处理：Test Agent 未修改生产实现或放宽断言。

根级回归其余四个失败与既有基线一致，和本次影响列表新增范围分开归因：

- `REG-01`：`Uc08DynamicLogFlowTest` S1 与 `LogFlowIntegrationTest` 的日志精确列表断言
  仍收到额外 `test step`。
- `REG-02`：`FlowServiceTest.prefersYamlKeysAndKeepsTheResolvedFlowKeyWhenLaterYamlOmitsIt`
  仍抛出 `IllegalArgumentException: message: must not be null`。
- `REG-03`：`PostgresRepositoryIntegrationTest.schemaUsesAggregateAndPluginTypes` 仍在
  schema 列计数断言得到 expected 4、actual 0。
