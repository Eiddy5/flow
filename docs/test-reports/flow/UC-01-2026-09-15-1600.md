| 场景 | 测试方法 | 状态 | 预期结果与结束状态证据 |
| --- | --- | --- | --- |
| S1 用户完成草稿的版本化生命周期 | `s1UserCompletesTheDraftLifecycle` | PASS | 已核对：两次保存都由系统分配版本，第二次保存形成同一租户、同一 Flow key 下的下一个版本而不是继续使用首次版本；新版本内容等于用户最后一次保存的内容，删除后草稿不再可编辑。结束：本场景草稿已经删除，不遗留可编辑草稿。 |
| S2 用户保存无效草稿并从发布失败中恢复 | `s2UserRecoversFromAnInvalidDeployment` | PASS | 已核对：无效内容可以作为带版本的草稿保存；发布被明确拒绝且不产生可运行版本；失败不会改变已保存草稿，再次保存修改内容时形成下一个版本。结束：用户删除草稿，且没有产生可运行版本。 |
| S3 两个租户独立管理内容相同的草稿 | `s3TenantsManageIdenticalDraftsIndependently` | PASS | 已核对：两个租户只能看到自己的草稿，任一用户的保存或删除不会改变另一租户的版本和查询结果。结束：两个租户都删除自己的草稿。 |
| S4 同一租户的不同用户创建和修改草稿 | `s4UsersInOneTenantPreserveCreationAudit` | PASS | 已核对：编辑用户的保存形成下一个版本；草稿仍显示最初创建用户和创建时间，同时显示最后编辑用户、编辑时间和最新内容。结束：草稿由租户 A 用户删除。 |
| S5 用户查询不存在或错误的 Flow key | `s5WrongFlowKeysDoNotAffectTheControlDraft` | PASS | 已核对：错误查询不会返回其他草稿或可运行 Flow，对照草稿的内容、版本和修改记录保持不变。结束：对照草稿由用户删除。 |
| S6 缺少租户身份的用户管理草稿 | `s6MissingTenantIdentityCannotManageDrafts` | PASS | 已核对：无租户用户的所有操作都被明确拒绝，系统没有创建新版本，也没有改变对照草稿。结束：对照草稿由所有者删除，拒绝操作没有遗留资源。 |
| S7 其他租户查询草稿 | `s7AnotherTenantCannotQueryTheDraft` | PASS | 已核对：租户 B 看不到该草稿，也不能得知草稿内容、版本记录或是否存在；租户 A 的草稿保持不变。结束：草稿由租户 A 所有者删除。 |
| S8 两个租户独立修改相同 Flow key 的草稿 | `s8TenantsReviseTheSameFlowKeyIndependently` | PASS | 已核对：两个租户的再次保存分别形成自己租户中的下一个版本；任一租户的内容、版本和修改信息都不会被另一租户的同 key 保存改变。结束：两个租户都删除自己的草稿。 |
| S9 其他租户删除草稿 | `s9AnotherTenantCannotDeleteTheDraft` | PASS | 已核对：租户 B 的删除被明确拒绝；租户 A 仍能查询自己的草稿，并在再次保存后获得下一个版本。结束：草稿最终由租户 A 所有者删除。 |
| S10 其他租户发布草稿 | `s10AnotherTenantCannotDeployTheDraft` | PASS | 已核对：租户 B 的发布被明确拒绝，没有为任何租户产生可运行版本，租户 A 的草稿版本保持不变。结束：草稿由租户 A 所有者删除。 |
| S11 用户在删除后继续使用同一 Flow key | `s11UserReusesTheFlowKeyAfterDeletingTheCurrentDraft` | PASS | 已核对：删除后的当前草稿不可查询或发布；新的保存获得比删除前更高的版本，不会复用已经删除的版本。结束：新草稿由用户删除。 |
| S12 用户混用草稿查询和可运行 Flow 查询 | `s12DraftAndDeployedFlowQueriesStaySeparate` | PASS | 已核对：已部署 Flow 的精确查询不会返回未发布草稿，草稿查询能够返回最新草稿的系统版本和原始内容。结束：用户删除草稿。 |
| S13 用户在草稿内容中填写系统管理字段 | `s13SystemFieldsRemainRawDraftSourceOnly` | PASS | 已核对：这些字段只作为草稿原文保存，不能改变系统分配的版本、草稿或删除事实及审计信息；发布被明确拒绝。结束：用户删除草稿，且没有产生可运行版本。 |
