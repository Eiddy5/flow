## 验证边界

本轮按公开 `FlowService` 完成保存、查询、发布和删除，没有绕过 Service 直接调用
Repository。版本和本次数据库行 `id` 由 Repository 分配；`companyId`、状态和审计
信息属于非 source 字段，由 Flow 领域依据 Session 和领域行为维护。S13 同时验证用户
source 可以原样保留这些同名字段，但不能覆盖领域事实或 Repository 分配结果。

每个场景均以新的随机测试租户运行。草稿保存、再次保存和删除都检查正版本；涉及连续
保存的场景还检查版本严格递增和数据库行 `id` 不复用。发布失败不消耗保存版本；删除
写入版本序列，删除后的同 key 新草稿继续取得更高版本。

## 测试结论

**PASS**。UC-01 全部 13 个场景已通过公开 Service、真实 Micronaut 与 PostgreSQL 16
验证。每次草稿保存及删除均进入同租户、同 Flow key 的递增版本序列；删除版本不会
复用，同 key 可在删除后以更高版本重新保存；不同租户各自维护独立序列。Repository
分配版本和本次数据库行 `id`，Flow 领域维护租户、状态与审计事实，source 无法覆盖
这些系统事实。Core/根工程最终补丁后的全量回归按主 Agent 的 UC-02 串行修订安排延期，
不影响 UC-01 的完整覆盖结论。
