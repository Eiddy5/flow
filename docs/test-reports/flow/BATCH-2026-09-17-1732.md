## HTTP 装配边界

UC16 使用随机端口 EmbeddedServer 和 JDK HttpClient，实际经过生产 SessionAuthenticationFilter、SessionArgumentBinder、WebhookTriggerController 与 Core/PG/Pulsar，再通过公开 ExecutionService 查询终态。测试不直接调用 Controller 代替网络。

验收范围外的认证使用每上下文随机 token 对应真实 AuthxSession；只替换 AuthxSessionAuthenticator 与 AuthxSessionFactory 的账号资料查询，保留真实 AuthX 会话/用户构造，按生产顺序初始化请求设备信息并恢复凭据绑定的可信公司。没有默认匿名身份。未验证真实登录、签发 token、认证数据库和账户授权规则。

HTTP 测试关闭默认配置文件加载，使用明确测试 properties，原因是 Server application.yml 与本地 paas-diagnostic JAR application.yaml 发生重复资源冲突。诊断管理 ServerService 使用仅测试替身，误调用即抛错；DiagnosticName 和实际响应过滤器保留。Server test configurations 排除未参与该路径的 paas-temporal，避免要求外部 Redis/Temporal。没有启动或伪造 Mongo/ES/Redis 业务服务，也未修改生产依赖配置。

因此本轮证明显式测试装配的真实 HTTP 触发闭环，不证明默认生产启动配置或完整认证宿主已可部署。
