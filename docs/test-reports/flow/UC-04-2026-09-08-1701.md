## 失败与反例

### CE-01：Pause 恢复后的后置异常未回到原等待点

- 用户输入：定义并发布含唯一 Pause 和真实失败后置 Task 的 Flow，启动并通过公开查询定位 Pause；提交 `{"decision":"APPROVED"}`。
- 故障输入：后续真实 RunnableTask 抛出 `uc04-downstream-failure`，未 Mock 状态推进。
- UC 预期：错误可见，Execution 与原 Pause 回到提交前 PAUSED，不遗留部分后置结果。
- 本次实际：恢复后公开查询 Execution 为 FAILED，断言 `expected: <PAUSED> but was: <FAILED>`。后续未执行的原子性断言不计为通过。

- 稳定性：本次整类、单方法（4.506 秒）和 core 模块均得到同一差异；此反例已在此前报告中记录，本轮完整延续。历史证据只能证明早于本次，不证明某个具体技术决策是引入点。
