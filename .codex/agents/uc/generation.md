# UC Agent 文档生成与覆盖审计

创建、移动、更新 UC Markdown 或维护索引时使用本文件。UC 章节、字段、写法、类型
覆盖矩阵和校验规则的唯一来源是 `.codex/skills/generate-uc/SKILL.md`。

## 领域与目录

- 一个 UC 只描述一个主要业务主题。
- 优先复用 `docs/uc/` 下已有领域，不创建近义目录。
- 新领域使用小写英文或连字符，并同时创建 `README.md`。
- UC 编号在整个 `docs/uc/` 中保持唯一。
- 文件路径使用 `docs/uc/<domain>/<UC-ID> <业务主题>.md`。
- 领域 `README.md` 维护 UC 清单、依赖和推荐验证顺序。

## 调用 `$generate-uc`

为单个 UC 准备符合
`.codex/skills/generate-uc/references/scenario-contract.md` 的内部契约，明确 `kind`；
任务类型 UC 同时明确 `targetTaskType` 和标准验证流程。随后调用 `$generate-uc`
生成文档并执行严格校验。

存在会改变用户结果的未确认需求时，先将问题返回主 Agent；确认前不将对应内容写入
`ACCEPTED` UC。生成过程不从架构设计或当前代码行为补全预期。

## 覆盖审计

交付前逐项确认：

- 每条已确认需求至少被一个场景覆盖。
- 每个相关业务规则体现在场景操作、预期结果或结束状态中。
- 每个 UC 有且只有一个主要类型，交叉场景具有唯一归属。
- 任务类型 UC 已完成对应覆盖矩阵审计，未确认项已集中返回主 Agent。
- 每个场景都有独立验证方式和完整用户闭环。
- 不同 UC 没有重复定义同一业务主题。
- 未确认内容没有进入已接受场景。

覆盖审计结果只在交付中汇总，不写入 UC Markdown。文档生成完成的判据是：UC 与
领域索引一致、引用有效、严格校验通过，覆盖审计中的每一项都有明确结论。
