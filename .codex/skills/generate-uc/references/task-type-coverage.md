# 任务类型 UC 覆盖参考

## 标准验证流程

每个场景独立定义并发布最小流程：

```text
开始 → 前置确定性任务 → 唯一目标任务 → 后置观察任务 → 结束
```

- 前置任务只准备目标任务需要的输入。
- 目标任务是本 UC 指定的唯一主要验证对象。
- 后置任务只证明目标任务的结果被后续流程正确消费。
- 为验证任务自身并发或交互规则，可以增加同类型目标任务；契约必须说明原因。
- 每个场景都启动独立流程实例，并查询到完成、失败或取消终态。

最终 UC 不使用代码块；把流程转换为 `验证流程` 字段中的用户语言。

## 通用候选维度

根据该 Task 已确认的业务契约审计：

- 合法配置、缺失配置、非法配置和边界配置。
- 正常成功、业务失败和未预期异常。
- 合法输入、缺失输入、非法输入和边界输入。
- 输出内容、输出缺失及结果被后续步骤消费。
- 重复执行、重复提交或重复回调。
- 超时、取消、重试和恢复。
- 用户离开或服务重启后继续处理。
- 多流程实例中的任务输入、输出和状态隔离。
- 用户权限、任务归属和多租户隔离。
- 任务结束后的待办清理及流程最终状态。

这些维度只用于发现候选场景。Task 没有已确认的超时、认领、转派、重试或回调
规则时，必须先询问用户，不能自行填充预期。

## PAUSE 候选维度

目标任务为 `PAUSE` 时，额外审计：

- 用户从自己的待办中查询并识别具体任务。
- 用户提交合法结果后只恢复对应流程。
- 找不到任务、任务编号错误或提交内容非法。
- 重复完成已经结束的任务。
- 其他用户或租户查询、完成任务。
- 同一用户存在多个待办时选择准确任务。
- 流程取消后继续完成原待办。
- 完成任务与取消流程发生竞争。
- 服务重启后重新查询并继续完成任务。
- 任务结果驱动后续步骤以及下游处理失败。

并行、汇聚、条件分支和嵌套本身属于流程编排。只有它们改变 PAUSE 的查询、完成、
结果隔离或清理行为时，才在 PAUSE UC 中保留交叉场景。
